# 천하군진 도시 정벌·운영 실행 안내 · 시드 101001

## 실행과 진입

소스 폴더에서 아래 명령을 실행한다. Node.js는 실제 package.json의 조건인 22.18 이상이 필요하다.

```powershell
npm ci
npm run dev
```

Vite가 출력하는 `Local:` 주소를 확인하고 브라우저에 그대로 입력한다. 보통 `http://localhost:5173/`이지만 사용 중인 포트에 따라 달라질 수 있으므로 실제 출력이 기준이다. `file://` 주소 차단 설정을 바꾸지 않는다. 배포된 단일 HTML을 직접 실행할 수 있는 사용자 환경에서는 그것을 사용할 수도 있다.

제목 화면 → **새 원정** → 군주 선택 화면 → **도시 정벌·운영 캠페인 (기본 시드 101001)**.

시드 입력을 비우면 이 버튼은 101001을 사용한다. 다른 시드를 입력하면 해당 시드로 새 캠페인을 만든다. 일반 군주 카드를 선택하면 기존 단일 원정을 시작한다. 저장 슬롯은 기존처럼 하나이므로 새 모드를 시작하면 현재 원정 저장을 대체한다.

시드 101001은 새 도시 규칙·빌드 DOM 테스트와 실제 규칙 자동 플레이에서 유효하다. 형양 → 성고 → 공현 3도시 완주를 자동 플레이로 확인했다. 사용자 실제 브라우저 플레이는 미검증이다.

## 첫 도시를 얻는 순서

1. 형양 성외에서 **정찰**을 선택한다. 원정 군량 18 → 16, 정보 2.
2. **향촌 보호 약속**을 선택한다. 군량 16 → 14, 주민 신뢰 2.
3. **내부 협력**으로 정벌한다. 군량 14 → 12, 성문 전투 없이 점령 방식 선택으로 이동한다. 성고에서는 이 방식이 잠겨 있다.
4. 처음에는 **향촌 공동 운영**을 선택한다. 안정과 주민 신뢰를 확보하고 공동 운영 문서를 받는다.
5. 도시 상태에서 민생·안정·치안·생산, 도시 식량·자재·인력과 군사 준비를 확인한다. 원정 군량 12와 도시 식량은 별개다.

같은 접근으로 수비대 설득을 선택하면 실제 설전 덱을 사용한다. 원정 군량 1을 쓰고 5라운드의 설전으로 진행하며, 카드 사용과 라운드 종료는 별도다. 성공·부분 성공은 점령으로 이어지고 약속이 도시 의무로 남는다. 실패하면 돌파·포위로 바꿀 수 있다.

전투를 체험하려면 새 캠페인에서 **보급 차단 + 나루 보급** → **성문 돌파**를 선택한다. 기존 군진 카드 전투가 시작되고 수비대의 실제 방비·체력이 줄어든다. 전투를 확인하고 돌아오면 도시 성문 피해가 남는다.

## 세 가지 도시 빌드를 비교하는 방법

처음부터 모든 시설을 갖추려 하지 않는다. 행정력 4 안에서 임명·시설·정책·인장을 먼저 준비하면 그 단계 카드 사용은 줄어든다. 한 장수는 한 단계에 한 업무만 수행한다. 남은 공용 카드도 역할 담당이 이미 일했다면 사용할 수 없다.

### 정착·구휼

첫 단계에서 **장수 임명 → 민생·기록에 정보(노장)**, **유민 정착 정책**, 제시된 **둔전소**, **향약 인장**을 선택할 수 있다. 각각 행정력 1이므로 카드 사용 전에 행정력이 끝난다. **행정 단계 종료**로 다음 단계에 간다.

다음 단계부터 구휼 창고 정책, 유민 등록·주거 정비·농지 개간을 상황에 맞게 섞는다. 민생 담당의 구휼과 교역·보급 업무인 향촌 조정을 다른 장수가 이어서 처리하면 향약이 발동한다. 공동 창고와 구휼 정책은 정산 안정에 실제 연계를 만든다. 식량을 계속 쓰므로 남은 비축과 다음 원정 군량을 함께 본다.

### 교역·물류

다른 새 캠페인에서는 **상단 긴급 복구** 점령을 선택하고 곽가를 **교역·보급**에 임명한다. **상단 보호·역참 정비**, **역참·상단 객사**의 조합을 목표로 한다. 청사진은 제안된 것 중 하나만 선택하며 원하는 시설이 처음부터 반드시 나오지는 않는다.

곽가의 현안 예측과 감찰은 드로우·현안 처리에 강하다. 진궁을 민생·기록에 추가 임명하면 고유 행정 정제와 기록 명령으로 비용을 줄일 수 있고 **청렴 감찰** 인장이 절감과 연결된다. 두 책사를 도시로 보내면 군단에서는 실제로 두 장수가 빠진다. 다음 원정 전 복귀 여부를 결정한다.

### 군사 거점

**군사 우선 통제** 점령 → 장료를 **치안·군사**에 임명 → **야간 통금·향병 훈련**, **군창 연계**, 제안되는 **향병 훈련장**을 목표로 한다.

향병 조직·긴급 동원은 빠르게 군사 준비를 올리지만 인력·민생·생산에 부담을 준다. 식량 8 이상에서 군사 명령을 쓰면 군창 연계가 한 단계 한 번 발동한다. 높은 군사 준비는 3단계 재공격과 다음 원정 보충병에 도움이 된다. 남은 인력을 모두 동원하면 실제 보충병을 보낼 인력이 줄어들 수 있다.

## 카드·현안·사업 확인

손패 카드를 선택하면 관련 구역이 강조되고 문맥 패널에 **사용 후 예상**이 나온다. 미리보기는 실제 규칙을 복제 상태에 적용한 결과다. 카드 선택만으로 자원을 쓰지 않는다. **명령 실행**이 실제 사용이다.

카드 사용은 행정 단계를 종료하지 않는다. 화면 하단 **행정 단계 종료**를 누르면 사업·현안·약속·생산·소비·위협을 정산하고 새 손패를 받는다. 선택된 카드가 없을 때 문맥 패널은 **단계 종료 후 예상**을 보여준다.

현안 제목을 열어 해결 계열과 기한을 확인한다. 현안은 관련 명령으로 총 2회 진전시키거나 기존 설전으로 해결할 수 있다. 기한이 지난 현안의 악화가 정산 기록에 남는다. 3단계 재공격은 위협과 현재 방어를 비교하여 미리 표시한다.

**시설 청사진** 서랍에서 수로·성문·역참 사업 명령을 확보할 수 있다. 명령 확보와 실제 공사 사용은 서로 다른 행동이다. 공사는 3회 진행 후 완공한다. 중간 진행은 즉시 생산 보너스로 표시하지 않는다. 동시에 진행하는 사업은 2개까지다.

**행정 덱 정제**에서 공용 카드를 강화·절감/유지 개조·제거한다. 비용은 행정력 1·자재 2다. 최소 덱은 8장이다. **집단·약속·협정** 서랍에서 도시 협정과 설전 약속의 이행 조건을 확인한다.

## 위임과 다음 원정

위임은 손패에서 같은 규칙으로 명령을 고른 뒤 정산하는 기능이다. 먼저 **위임 예상 변화**를 확인한다. 시설·임명·정책·출발은 자동으로 선택하지 않는다. 위험 대응이 필요하면 직접 명령을 사용한 후 남은 명령만 위임할 수 있다.

5단계 정산이 끝나면 도시 결과와 지원 준비 화면이 나온다. **원정 군량 / 보충병 / 정찰 정보** 중 집중할 지원을 고른다. 도시 식량·인력 차감, 도로 상태·거리·치안, 운송 손실과 출발 병력·군량을 확인한다. 비축을 지나치게 줄이면 도시 안정에 손해가 남는다.

필요하면 **주둔 장수 복귀**를 먼저 선택한다. 도시 식량 2·군사 준비 5를 쓰며 해당 정책 담당이 공석이 된다. 준비가 되면 성고 또는 공현의 **지원 발송 · 원정 출발**을 누른다. 원정 교리를 다시 고르고 기존 지도에서 실제 경로를 진행한다. 군량이 적으면 보급·휴식·외교를 고려한다. 마지막 거점에서 다음 도시 접근·정벌 방식을 선택한다.

## 저장 복원 수동 확인

접근 준비 1개 선택 후, 설전 또는 전투 진행 중, 임명·카드 사용 후, 공사 1/3 또는 2/3 상태, 위임 정산 후, 지원 발송 직후에 각각 새로고침한다. 제목 화면의 **이어하기**에서 도시 지표·단계·손패·공사·현안·장수 위치·원정 군량과 병력이 유지되는지 비교한다. 완료된 지원이 두 번 더해지면 문제로 기록한다. 같은 주소와 같은 브라우저 저장소를 사용해야 한다.

자동 테스트는 이 상태들의 저장·복원을 확인했다. 사용자가 실제 브라우저에서 확인하기 전까지 수동 복원과 시각 결과는 미검증이다.

## 데스크톱·모바일 점검

데스크톱에서 구역 6개·문맥 패널·손패·정산 버튼이 겹치지 않는지, 긴 현안과 글자 크게 모드가 잘 읽히는지 확인한다. 손패는 가로 스크롤, 역사 지도는 휠 상하·Shift+휠 좌우·Ctrl+휠 확대/축소를 사용한다.

모바일에서는 두 열 구역도·세로 문맥 패널·하단 손패가 선택과 스크롤을 가리지 않는지 확인한다. 임명 선택 목록, 청사진, 긴 정산 서랍, 지원 드롭다운을 터치로 검사한다. 가로 화면도 점검한다. Tab·Enter·Space로 버튼과 선택 목록을 사용할 수 있는지, 글자 크게·고대비·운영체제 연출 감소를 켰을 때 읽기와 조작이 유지되는지 확인한다. 실제 휴대폰·스크린 리더 결과는 미검증이다.

자동 검증 재실행은 `npm test`, `npm run build`, `npm run sim:cities`, `npm run sim:campaign`으로 할 수 있다. 자동 테스트 통과는 사용자 재미나 실제 화면 품질의 통과를 뜻하지 않는다. 브라우저 보안 정책과 관리자 설정은 변경하지 않는다.
