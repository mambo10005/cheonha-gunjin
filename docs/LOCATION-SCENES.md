# 도시 장소 장면

## 이번 구현 범위

도시 탐색과 거병 후 내정이 같은 장소 장면 상태를 사용합니다. `LocationSceneDefinition`은 도시의 장소 ID와 아키타입으로 구역, 조사 대상을 제공하고, `LocationSceneState`는 방문 구역, 선택 인물, 대화/조사 단계, 조사한 대상과 단서를 저장합니다. 장소 효과와 의뢰 결과는 기존 사건·내정 엔진이 확정하므로 화면을 다시 그리는 것으로 시간·자원·난수를 소비하지 않습니다.

장소 장면은 객사, 창고, 시장, 관청, 병영, 성문, 서원/문서고, 향촌/민가, 사당, 역참, 나루, 공방, 성외 위험 장소를 포함한 현재 지도상의 모든 장소에 생성됩니다. 장소 데이터는 `src/data/location-scenes.ts`의 아키타입별 구역과 조사물로 제공됩니다. 시각 구성은 공통 장면 컴포넌트와 장소별 벡터/색·공간 변형을 사용합니다. 객사는 기존 전경과 인물 초상을 재사용합니다. 창고 책임자 초상은 코드 내 SVG로 그리고, 호위 대표는 새 SVG 초상을 사용합니다.

거병 후에도 공통 장면 안에 기존 행정 명령을 배치합니다. 창고와 성문이 의뢰의 실제 수송 목적지로 확보되면 기존 도시 설립 처리에 같은 확보 상태가 전달되어 창고 비축 시설로 이어집니다. 이전 저장에는 `locationScenes`가 없어도 계속 읽을 수 있으며, 완료된 의뢰 영수증과 이전 버전의 호송 승인 저장을 `campaign-save.ts`에서 보정합니다.

## 창고 호송 수직 단면

전위의 「수레가 지나갈 길」은 다음 4단계로 진행됩니다.

1. 객사에서 의뢰를 수락하고 창고로 이동합니다.
2. 창고 앞마당에서 수레, 통로, 호위 인력을 실제로 각각 조사하고, 창고 사건을 조사합니다. 조사물은 시간 1회만 소비하며 중복 조사로 시간을 다시 쓰지 않습니다.
3. 창고에서 실제 해결 방식을 고릅니다.
   - 호위 계약: 자금 3을 지불하고 단기 계약을 맺습니다. 채무 1과 군량 약속을 남기고 계약 보수와 책임을 기록합니다.
   - 무장 대결: 저장된 실제 대결 규칙을 시작합니다. 승리·무승부는 통행 합의로 이어지고, 패배·기권도 의뢰를 실패 처리하지 않으며 계약이나 우회로를 남겨 둡니다.
   - 설전: 실제 카드 기반 설전과 조건 판정을 사용합니다. 결과는 의뢰 증거와 결론에 저장됩니다.
   - 대체 통로: 수레·통로·짐꾼 조사와 정보 1, 지도 또는 노숙 동행이 필요합니다. 시간 2와 노출 1을 지불하고 노숙의 신뢰·협력 실적을 올립니다.
4. 성문으로 이동해 호송 명령을 실행합니다. 수레·군량의 도착과 하역을 실제로 기록하고 준비 군량을 받습니다.
5. 객사로 돌아가 전위에게 직접 보고합니다. 보고 전에는 보상, 훈련, 거병 계획을 지급하지 않습니다. 보고 대화는 무장 대결, 계약, 우회로, 설전 결과에 따라 달라집니다.

현재 계약은 “단기 1회 호송” 한 종류이며 보수/기간/사고 책임을 여러 계약안 중에서 조정하는 선택은 아직 구현하지 않았습니다. 공동 호위 전술·현장 전투도 아직 미구현입니다. 군량 장부·열쇠·짐꾼·수레·통로의 개별 조사와 경로/결과는 실제로 저장됩니다. 계약과 설전, 대결, 우회로 모두 기존의 실제 게임 규칙을 사용합니다.

## 조작과 저장

- 위쪽 구역 버튼으로 장소 내부를 전환합니다.
- 인물 목록에서 책임자, 방문 인물, 의뢰 인물, 동행자를 고릅니다. 선택한 상대의 초상과 대사가 화면에 나타납니다.
- 사물 카드를 조사하면 한 번만 준비 시간이 들고, 확인 단서가 저장됩니다.
- 창고 의뢰의 선택과 설전/대결은 화면을 닫아도 저장됩니다. 결론 화면의 지도 이동은 위치 변경일 뿐 의뢰 보고를 완료하지 않습니다.
- 객사에는 같은 장소 장면 외에 기존 객사 전용 소개·의뢰·소문·숙박 기능이 포함됩니다.
- 객사 장면은 구역·인물·대화를 객사 상태 하나로 관리합니다. 위쪽 구역 버튼(`inn:area:*`)과 공통 장면의 `scene:zone:*`은 같은 객사 방을 바꾸고, 인물을 고르면 그 인물이 있는 구역으로 함께 이동합니다. 안쪽 방은 주인 소개 전까지 잠겨 있습니다.
- 객사 안에서는 구역 선택, 인물 목록, 지도 복귀 버튼을 한 번씩만 보여 줍니다. 인물 카드는 오른쪽 열(좁은 화면에서는 아래)에만 있고, 객사 실내 그림은 장면 그림과 대화 무대를 겸합니다.

## 검증

규칙 테스트는 `tests/location-scene.test.ts`와 `tests/inn.test.ts`, 공통 UI 입력과 DOM 테스트는 `tests/city-exploration-ui.test.ts`에서 실행합니다. `tests/location-scene.test.ts`는 모든 도시 장소의 데이터 정의, 구역·대화·조사 저장/복원, 중복 시간 방지, 창고 단서 요구, 이전 의뢰 저장 변환을 확인합니다. `tests/inn.test.ts`는 대결 패배 뒤 계약, 실제 성문 수송, 객사 보고까지 검사합니다.

2026-10-10 객사 레이아웃 정리 후에는 클라우드 작업 환경의 헤드리스 Chromium(Playwright)으로 1440·1024·768·390px 너비 화면을 캡처해 가로 넘침과 인물 카드 겹침이 없는지 확인했습니다. 이는 자동 화면 캡처 확인이며 사람이 직접 플레이한 결과는 아닙니다. 터치 입력과 실제 기기 해상도는 여전히 미검증입니다.

이 테스트는 코드의 규칙 및 jsdom DOM 테스트입니다. 실제 브라우저에서 수동으로 플레이한 결과는 아닙니다. 브라우저 정책 차단을 재시도하거나 우회하지 않았습니다. 실제 브라우저의 해상도·애니메이션·마우스/터치 입력은 미검증입니다.

## 현재 한계

모든 장소에 공통 구역·인물 슬롯·조사 UI와 아키타입별 코드 기반 공간 표현을 제공하지만, 모든 도시에 고유한 역사 인물·전용 이벤트와 전문 일러스트를 각각 추가한 것은 아닙니다. 책임자는 공통 벡터 표현을 쓰며 창고 책임자의 전용 초상 SVG는 별도 제공됩니다. 성문을 제외한 다수의 장소 사건은 기존 탐색 이벤트를 유지합니다. 거병 후에는 기존 내정 기능을 공통 장면 안에 놓았으며, 새 창고 운영 사업(정기 보급, 장부 감찰, 비밀 비축 등) 전체를 추가한 것은 아닙니다.
