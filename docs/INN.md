# 객사: 인물·도시 의뢰 수직 단면

기준: 2026-10-10 작업본. 기존 천하군진의 도시 탐색·거병·설전 덱·무장 대결·인재·저장을 확장했다. 아래 자동 결과는 규칙과 DOM 검증이며, 실제 브라우저 화면과 사용자 플레이는 **미검증**이다.

## 기존 문제와 변경

객사 인물과 요청이 긴 패널로 쌓이고, 주요 인재의 부탁을 즉시 완료하는 경로가 있었다. 객사를 선택 가능한 초상과 주인공·상대의 양쪽 원화 장면으로 바꿨다. 순욱·노숙·전위의 기존 즉시 부탁 명령은 도시 탐색 규칙과 내부 인재 명령 양쪽에서 차단했다. 기존 다른 장소의 단순 소규모 부탁까지 전부 단계형으로 바꾼 것은 아니다.

인물 선택, 대화, 부탁 제안, 보고, 숙박, 소문, 우발 대화는 판별 가능한 `InnView`로 관리한다. 실제 설전·대결은 기존 도시 탐색의 해당 상태를 사용하며 모순되는 화면 플래그를 추가하지 않았다. 선택 화면에는 다른 손님의 작은 초상 버튼이 있어 지도로 나가지 않고 상대를 바꿀 수 있다.

## 공간과 인물

| 구역 | 실제 활동 |
| --- | --- |
| 주인 자리 | 주인 대화, 출입 기록, 소문 구매, 개인 부탁, 소개, 숙박 |
| 객당 | 방문 손님 초상, 인물 선택, 심운·허림의 대화에 참여 또는 몰래 듣기 |
| 안쪽 방 | 소개 후 구역 접근, 순욱의 비공개 접견, 부탁과 보고 |
| 뒤뜰 | 전위 선택, 실제 호위 시험 대결. 시간·자금·피로와 1회 제한 적용 |

객사 주인 **한복**, 행상 **심운**, 여행 서생 **허림**은 게임용 창작 인물이다. 객사 주인 한복은 역사 인물 한복을 재현한 설정이 아니다. 순욱·노숙·전위의 도시 배치와 본 의뢰의 줄거리도 역사적 사실을 주장하지 않는 창작 사건이다.

한복은 손님과 객사의 신용을 지키는 지속 인물이다. 주인 신뢰 0~10, 객사 평판 −5~5, 들은 대화, 소개 여부, 해결 기록이 저장된다. 평판이 낮으면 소문 비용이 증가한다. 주인 신뢰나 소개장에 따라 안쪽 방 소개 비용이 면제된다. 기본 휴식·공개 정보는 낮은 신뢰에서도 가능하다.

인사, 오늘의 손님, 도시 분위기, 관청, 상단, 병영, 소문, 소개, 개인 부탁, 숙박·식사, 두 손님 관찰의 11개 주제를 제공한다. 관청·상단·병영·관찰은 인사로 신뢰를 쌓은 뒤 나타난다. 같은 주제를 다시 읽어도 처음의 신뢰·정보 보상을 반복 지급하지 않는다. 소개와 소문은 비용을 확인하고 실제 행동으로 이어진다.

방문 구성은 첫 방문/재방문과 시간 구간, 진행 중 의뢰, 파견·이탈 상태에 따라 달라진다. 손님은 주인 외 최대 5명이다. 숙박 뒤 구성을 갱신하며 진행 중 의뢰인은 보고를 기다린다. 전체 인물의 정교한 시간표 시뮬레이션이나 다수의 무작위 우발 사건은 이번 범위에 포함하지 않았다.

## 원화와 표현 상태

새로 생성한 원화는 주인 한복·순욱·노숙·심운·허림의 반신 5종과 객사 내부 배경 1종이다. 주인공은 기존 캠페인 원화, 전위는 기존 전투 원화를 재사용한다. 실제 생성 원본·크기·투명도·경로는 [에셋 기록](art/INN-GENERATED.json)에 있다. 허림은 테두리 결함을 이미지 생성 도구로 수정한 불투명 녹색 배경 원화를 사용한다. WebP 변환은 저장 형식 변환만 수행했다.

`inn-presentation.ts`에서 초상 경로·위치·크롭과 구역 배경 위치를 관리한다. 주인과 상대는 실루엣 대신 생성 원화를 표시한다. 발언·경계·협력은 동일한 마스터 원화의 조명·배치 상태다. **서로 다른 포즈별 원화를 모두 제작한 것은 아니다.** 4구역은 한 내부 원화를 크롭해 사용하고 밤에는 조명 처리를 한다. 아침·낮·밤·안쪽 방·뒤뜰의 독립 원화 5종은 미완성이다. 이미지 누락 시 별도의 인장 fallback도 아직 추가하지 않았다. 모든 현재 등록 원화는 패키지에 포함한다.

## 소문과 도시 연결

소문은 출처·신뢰도·관련 장소·인물·만료·확인 수단을 가진다. 구매 전 범주와 캠페인당 최대 2회 제한, 시간 1·자금 1(낮은 평판이면 2)을 표시한다. 성문과 창고를 발견 처리하고 인재의 단서를 공개하며 `소문 속 비축 창고` 의뢰를 제안한다. 실제 목표 장소를 조사하면 소문을 확인된 정보로 바꾼다. 불확실한 문장을 역사적 사실로 표시하지 않는다.

초기 소문 표본은 통행 기록과 창고 비축에 집중한다. 모든 소문 유형을 구현했다고 주장하지 않는다. 만료 시점은 기록하고 표시하지만 만료된 소문을 통한 별도 사건 소멸까지 구현하지 않았다. 의뢰 자체는 기한이 지나면 만료되어 보고 보상을 받을 수 없다.

## 단계형 의뢰

정의 데이터에는 의뢰인·제목·동기·위험·수락 비용·기한·장소별 단계·접근·보고 보상·거병 후 영향이 있다. 런 상태에는 상태, 현재 단계, 수락 시점, 기한, 사용한 접근, 증거, 결과, 결론, 보고 영수증, 실제 지급한 보증금을 저장한다. 상태는 제안/수락/진행/보고 대기/완료/실패/만료/포기다. 정의와 런 상태를 분리해 같은 보상을 매번 새로 생성하지 않는다.

| 의뢰 | 실제 장소와 과정 | 보고 결과 |
| --- | --- | --- |
| 순욱: 피난민 추천서의 구휼 보증 | 객사 출입 기록 → 문서고 조사 → 실제 설전/소개장/유료 사본 → 보증 범위 선택 → 객사 보고 | 신뢰·실적·경험, 성문 내응 계획, 정보·명분·권한 공유 약속 |
| 전위: 수레가 지나갈 길 | 창고 조사 → 성문 호위 대표와 실제 대결 또는 자금 2 경비 계약 → 객사 보고 | 신뢰·실적·경험, 훈련, 군영 장악 계획 |
| 노숙: 두 장부의 간격 | 시장 조사 → 창고 설전/손실 분담 → 결론 → 객사 보고 | 신뢰·실적·경험, 상단 관계 |
| 주인: 잃어버린 소개장 | 시장 전달 경로 → 민가 확인 → 객사 보고 | 주인 신뢰 2·안쪽 방·소개장 |
| 소문: 비축 창고 | 성문 통행 기록 → 창고 실제 비축 → 객사 보고 | 지도 물품·정보 1·주인 신뢰 2 |

순욱 부탁의 기존 문구를 확인해 **구휼 보증**을 유지했다. 새 이야기는 이 문구를 조사형 사건으로 확장한 것이다. 수락에는 시간 1·군량 보증금 2를 실제 지급한다. 수락만으로 신뢰·실적·카드를 받지 않는다. 첫 단계는 객사 주인의 공개 기록, 신뢰를 통한 비공개 기록, 실제 사용한 카드의 정보로 처리한다. 문서고에 직접 이동·진입해야 다음 단계가 열린다. 의뢰 추적기에 현재 목표·남은 기한·실제 가능한 접근과 지도 목표 표시를 제공한다.

설전은 기존 장수별 덱·논법·손패·집중·라운드·반론 규칙을 실제로 실행한다. 동행 보좌, 거병 카드에서 대응되는 논거, 장부 증거를 재사용한다. 현지 기록 보증인의 설전은 기존 향촌 대표 원형을 재사용하며 상대 장면에는 허림·심운의 생성 원화를 연결했으며 호위 시험은 전위 원화를 재사용한다. 전용 상대의 포즈·대사 전체를 새로 제작한 것은 아니다. 결렬 시 피로 2·노출 1이 남고, 같은 대결을 다시 굴리지 못한다. 결렬 뒤 시간과 노출을 들인 추가 조사 또는 비용을 낸 대체 방식으로 계속한다.

무장 대결은 `객사 호위 대표`의 실제 공격 패턴·체력·전술·기권을 사용한다. 동행 군사 인재의 방비와 준비 카드의 전술을 반영한다. 전위 의뢰의 패배는 유료 경비 계약으로 우회 가능하다. 뒤뜰 시험은 캠페인당 한 번이며 승리 훈련 1·주인 신뢰 1, 패배/기권 피로 2를 기록한다.

완전 검증은 확인한 사실의 보증으로, 조건부 보증은 부분 성공과 채무·구휼 의무로, 확인된 불일치 공개는 추가 노출로 연결한다. 근거 없는 공개나 실패 전 추가 조사로 단계를 건너뛰는 명령을 거부한다. 기한을 넘기거나 포기하면 비용 환급과 재수락 보상이 없다.

## 카드·물품·협력

기존 탐색 카드를 장소에서 실제 사용하면 관련 카드 접근이 열린다. 별도의 객사 카드 수십 종을 추가하지 않았다. 소개장·장부 제출은 상대와 목적을 표시하고 같은 제출 버튼을 다시 눌러야 소비한다. 소개 비용 할인은 소개장을 보유만 확인하고 소비하지 않는다. 보상 물품은 기존 슬롯·대기 물품 규칙을 따른다. 대기 물품이 있으면 먼저 정리한 뒤 보고해야 한다.

보고는 객사·현재 의뢰인·보고 단계·기한을 확인하고 시간 1을 소비한다. 보상 영수증을 저장해 한 번만 지급한다. 주요 인재에게 신뢰 15·부탁 완료·실적·경험 1을 주며, 주인공 경험과 계획 발견을 기존 엔진에 반영한다. 이후 **협력과 등용을 별도로 선택**한다. 지원 카드의 실제 사용/관계 협력, 신뢰와 자금 조건, 개인 카드 선택·편성은 기존 인재 규칙을 사용한다. 보고 자체가 개인 카드를 자동으로 여러 장 복제하지 않는다. 동행 교체는 상단 `인물·동행` 패널을 계속 사용한다.

## 거병 후와 저장

거병 전 객사 관계·해결 의뢰·아이템·계획·약속을 그대로 유지한다. 도시 시설과 약속 변환은 기존 도시 운영 규칙에 따른다. 같은 객사에서 인재 관계를 확인하고 신뢰 2 정보망을 턴당 한 번 사용할 수 있다. 정보망은 도시 행정력 1·세력 금고 1을 소비해 명망 1을 올린다. 실제 세계 외교 명령으로 교역·휴전·종속을 체결하며 자원·행동력·재고·계약 기간을 적용한다. 새 외지 인재 스폰이나 객사만의 사절 퀘스트는 미완성이다.

기존 도시 탐색 저장에 `inn`이 없으면 진입 시 생성한다. 기존에 완료한 주요 부탁은 `legacy-receipt` 완료 영수증으로 옮기고 보상을 다시 지급하지 않는다. 런과 캠페인 저장 형식의 기존 구조를 유지하면서 객사 상태·의뢰 단계·설전/대결 연결·중복 기록을 검증한다. 현재 원정의 저장을 초기화하거나 결과를 재굴리지 않는다. 과거 정적 거병 화면 저장을 새 도시 탐색 전체로 강제 변환하는 변경은 이번 범위가 아니다.

의미 이벤트에는 입장·주인/손님 선택·도착·주제·소문·의뢰 제안/수락/진행/보고·숙박·관계·도시 변화가 포함된다. 실제 카드 사용·설전·대결·등용·아이템 사건은 기존 이벤트 경로를 사용한다. UI는 엔진의 기록과 상태를 읽으며 보상을 따로 계산하지 않는다. 모든 포즈와 애니메이션이 이벤트별 재생 큐로 세분화된 것은 아니다.
