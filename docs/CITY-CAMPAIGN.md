# 도시 정벌·운영 캠페인 구현

이 문서는 실제 구현 범위와 검증의 한계를 기록한다. 전국 확장이 아니라 기존 하남윤 지도 자료를 사용한 형양·성고·공현 3개 도시의 지역 수직 단면이다. 기존 단일 원정은 군주 선택으로 계속 시작할 수 있다.

## 저장소 분석과 범위 결정

| 확인 질문 | 기존 상태와 이번 결정 |
|---|---|
| 결전 승리는 무엇을 변경하는가? | 기존 `finishBattle`은 병력·군량·진형을 원정에 반영하고 `victory`로 종료한다. 기존 UI는 메타 기록 후 원정 저장을 지운다. 캠페인에서는 같은 전투 결과를 점령 방식 선택으로 연결하고 저장을 유지한다. |
| 도시 소유권이 있는가? | 기존 역사 지명·활동 거점에는 소유권이 없다. `CampaignState.cities`에 점령 도시와 장기 상태를 추가했다. |
| 병력·군량은 어디에 속하는가? | 기존 `RunState`의 군단 자원이다. 도시 식량·인력·자재는 `CityState`, 출전 병력·군량은 계속 `RunState`에만 둔다. |
| 장수의 도시 이동은 가능한가? | 기존은 원정 진형·영입·교체뿐이다. 도시 임명은 실제 군단에서 장수를 제거한다. 임명 중복·최소 출전 1명·진형 정원을 검사한다. 운영 종료 도시에서는 식량 2·준비 5로 복귀할 수 있다. |
| 원정 성장과 메타 해금은? | 교리·장수 성장·덱·설전 덱은 원정 상태, 기존 메타는 원정 횟수·승리·장수·난도 해금이다. 새 캠페인 운영 빌드 해금은 캠페인에만 저장하며 영구 생산력 보너스를 주지 않는다. |
| 상태는 어떻게 분리하는가? | `RunState.campaign`이라는 선택 필드에 독립된 `CampaignState`를 넣는다. 저장 봉투는 하나라 군단·도시 간 이전을 함께 저장한다. 캠페인이 현재 원정 전체를 또 복사해 보관하지 않는다. |
| 정벌 후 같은 원정이 계속되는가? | 기존 원정은 결전으로 종료한다. 새 모드는 점령·내정·지원 이후 새 시드의 원정을 만들고 캠페인과 실제 덱·군단을 보존한다. 일시 교리·경로·원정 협정은 새 원정에서 초기화한다. |
| 역사 인접 관계는? | 기존 형양·성고·공현 지명과 동서 맥락을 사용한다. 형양–성고, 성고–공현, 형양–공현 우회 통로는 게임용 연결이다. 실제 도로·거리나 190년의 도시 지배 관계라고 주장하지 않는다. |
| 고정 지리와 시드 사건은? | 도시 ID·지세·구역·지역 연결은 고정, 초기 지표 변동·현안·청사진·행군 활동·덱 순서는 RNG로 분리한다. |
| UI·자동 플레이·저장은? | 기존 군진 전투·덱 설전 UI를 재사용한다. 새 도시 구역도·문맥 패널·손패·서랍을 추가한다. 저장 버전 6, 캠페인 스키마 1, 데이터 `henan-cities-1`. |

## 실제 캠페인 순환

첫 도시 성외 접근 → 준비 2개 → 정벌 방식 → 점령 방식 → 내정 5단계 → 지원 집중 선택 → 도시 자원 차감 → 인접 도시 원정 → 기존 8행군과 전투·설전·외교 → 성외 접근 → 다음 도시 점령.

첫 형양은 수직 단면을 빠르게 체험하도록 성외에서 시작한다. 후속 원정은 기존 역사 지도·경로·지형·보급·성장·전투를 실제로 진행한다. 원정 지도 구간은 출발 도시와 목적 도시의 기존 지명 위치를 연결하는 창작 행군 약도다. 성외에서 어떤 정벌 방식을 쓸지 다시 결정한다.

접근 준비는 정찰(정보 +2), 나루 보급(원정 및 점령 식량), 향촌 보호(점령 안정), 보급 차단(수비대 체력·방비 감소), 강제 징발(즉시 군량과 도시 피해·관계 손실)이다. 같은 준비를 반복할 수 없다.

정벌은 기존 군진 카드 전투로 성문 돌파, 기존 설전 덱으로 수비대 설득, 군량 8·병력 4를 쓰는 포위, 정보·주민 신뢰로 여는 내응이다. 성고에서는 내응을 사용할 수 없다. 설전의 부분 합의와 약속도 점령과 도시 의무에 저장된다. 패배는 군단 후퇴와 재정비로 처리하고 이미 운영한 도시를 지우지 않는다.

점령 방식은 엄정 접수, 향촌 공동 운영, 군사 우선 통제, 상단 긴급 복구 4개다. 안정·치안·준비·식량·자재·집단 관계·시작 카드가 달라진다. 돌파 피해는 성문과 농지에 남으며 시설 정지·복구와 연결된다.

## 내정과 세 빌드

핵심 지표는 민생·안정·치안·생산 4개다. 40 이상을 안전, 30 미만을 위험으로 표시한다. 군사 준비는 별도 방어·보충 지표다. 도시 식량·자재·인력과 원정 군량·병력은 화면과 이전 규칙에서 구분한다.

6개 고정 구역은 관청·시장·농지·창고·병영·성문이다. 구역 선택, 피해, 제한된 시설, 명령 대상 강조, 시설 복구·강화가 구현되어 있다. 자유 건물 위치 배치는 없다.

내정은 5단계, 기본 행정력 4(안정 25 미만이면 3), 기본 손패 5장, 손패 최대 8장, 단계당 명령 최대 8회다. 장수는 단계마다 한 업무를 수행하며 피로 5 이상이면 안정 부담이 생긴다. 미사용 장수 피로는 정산에서 회복된다. 단계 종료는 사업 → 현안 악화 → 약속 → 정책·시설 생산 → 주민·주둔 소비 → 위협 → 새 단계 순서다.

| 빌드 | 대표 실제 조합 | 기회비용 |
|---|---|---|
| 정착·구휼 | 정보(노장) 민생 담당 + 유민 정착·구휼 창고 + 공동 창고·둔전소 + 등록·개간·구휼 | 민생·안정을 회복하지만 구휼 식량과 인력을 소비한다. 초기 행정 투자로 즉시 카드 사용이 줄어든다. |
| 교역·물류 | 곽가 교역 담당 + 상단 보호·역참 정비 + 상단 객사·역참 + 통행 허가·감찰·호송 | 자재·수송 기반이 강하지만 치안 손실과 협정 의무에 대응해야 한다. |
| 군사 거점 | 장료 치안 담당 + 통금·향병 훈련 + 훈련장 + 향병·동원·성문 공사 + 군창 연계 | 방어·보충이 강하지만 민생·인력·생산을 소비한다. |

진궁의 기록 명령은 다음 카드 행정력 −1, 정보의 구휼·외교는 민생·주민 신뢰, 장료의 군사·토목은 빠른 준비·자재와 민생 손실, 곽가의 정보는 카드 드로우·현안 예측을 제공한다. 총점으로 자동 추천하지 않는다. 임명 시 고유 카드가 실제 덱·손패에 들어가고 해임 시 제거된다.

공용·도시·점령·장수·협정·시설 카드를 포함한 내정 카드 21종을 정의했다. 초기 덱은 10장이다. 획득·강화·절감/유지 개조·제거, 버림·재섞기·임시 생성·소멸이 구현되어 있다. 고유 카드와 임시 카드는 정제 대상에서 제외한다.

정책 6종은 담당 장수·행정력·지속 기간과 부작용을 가진다. 활성 2개 제한이다. 행정 인장 4종(공역 장부·향약·군창 연계·청렴 감찰)은 2개 제한이며 각각 단계당 한 번만 발동한다. 시설 8종은 청사진 3개 중 하나를 선택하고 나머지 제안을 포기한다. 3·5단계에 새 제안이 오며 구역당 1개·도시 전체 3개 제한이다.

현안 6종은 군량 부족·유민 유입·잔당 잠복·시장 독점·관리 부패·농지 침수다. 관련 계열 명령·장수·설전·공사로 해결하고 기한을 넘기면 지표·관계·자원·위협에 흔적이 남는다. 장기 사업은 수로·성문·역참 3개, 동시 2개, 진행 3회다. 유지 인력·담당 공석·방치와 완공 효과를 처리한다. 사업 중간 저장도 복원한다.

향촌·상단·유민 3집단 관계는 −3~3이다. 물류 또는 공동 방어 협정은 활성 1개·비용·3단계 지속·이행 의무를 가진다. 물류는 식량·자재·호송 카드·다음 원정 통행, 방어는 준비·식량 소비·다음 전투 지원으로 연결된다. 도시 설전은 실제 기존 덱을 사용하고 약속을 CityState에 저장한다.

3단계 종료의 잔당 재공격을 예고한다. 준비 + 치안 절반 + 방어 협정을 위협과 비교하여 자원·안정·성문 피해를 처리한다. 도시를 잃어 전체 캠페인이 즉시 끝나는 방식은 사용하지 않았다. 운영 종료는 안정 도시·기능 도시·불안정 도시·군사 주둔지로 구분한다.

## 지원과 위임

도시 식량·인력을 실제 차감하고 도로 상태·거리·치안·역참·연결된 점령 도시 수로 수송량과 손실을 계산한다. 식량 비축 4 미만으로 출발하면 안정 부담이 남는다. 원정 시작 군량은 재정비 기본 8 + 실제 배송량, 병력은 기존 병력 + 보충 인력 2배(최대 병력 제한), 후퇴 후 출전 최소 병력은 20이다. 이러한 재정비 기본값은 도시에서 온 자원이라고 표시하지 않는다. 원정 덱·군단·설전 덱은 보존하고 임시 교리는 다시 선택한다.

위임은 민생·군사·생산·현안·빌드 연계·지원·무작위·자원 보존 8개 방침이다. 손패에서 유효한 명령 최대 8회 후 정산하며 직접 사용과 같은 규칙 함수를 호출한다. 위임 미리보기는 복제 상태로 동일 함수를 실행한다. 건설·임명·정책·징발·출발은 위임하지 않는다. 도시가 늘어나도 예전 도시를 매 단계 다시 운영해야 하는 구조는 아니다. 완성된 도시의 빌드는 보관되며 자동으로 무료 생산을 누적하지 않는다.

## 저장과 변경 파일

기존 저장 1~5는 버전 6으로 승격하며 기존 원정·RNG·진행 중 활동을 유지한다. 캠페인 데이터가 없으면 기존 모드로 계속 진행한다. 결전 승리를 임의의 첫 도시로 변환하지 않는다. 손상되거나 모순된 도시 데이터는 거부하지만 저장 원본을 자동 삭제하지 않는다. 캠페인 데이터 버전이 다른 경우도 자동으로 도시를 새로 만들지 않는다.

주요 파일: `src/core/city-types.ts`, `city.ts`, `city-validation.ts`, `src/data/cities.ts`, `src/ui/city-screen.ts`, `city-screen.css`, `src/sim/city-benchmark.ts`, `city-campaign.ts`, `city-campaign-benchmark.ts`, `tests/city.test.ts`, `city-ui.test.ts`.

연결 변경: `types.ts`, `run.ts`, `social-run.ts`, `save.ts`, `save-validation.ts`, `geography.ts`, `map-intel.ts`, `data/enemies.ts`, `ui/main.ts`, `regional-atlas.ts`, `expedition-map.ts`, `package.json`. 기존 저장 버전 기대값을 검사하는 회귀 테스트도 6으로 갱신했다. 이전 카드 수량 표시와 지도 스크롤 개선을 유지했다.

## 검증을 해석하는 방법

최종 빌드·전체 자동 테스트·도시별 계측 결과는 배포 `verification/city-build.log`, `city-all-tests.log`, `city-benchmark.log`, `city-campaign.log`와 `docs/verification/city-balance.json`, `city-campaign.json`을 기준으로 한다.

도시 빌드 계측은 12시드 × 3도시 × 3빌드 × 7행동 방침 = 756표본이다. 미리보기-실행 일치와 매 단계 저장 복원을 함께 검사한다. 별도 캠페인 계측은 실제 기존 행군·카드 전투·활동을 거치는 자동 플레이다. 완주율과 실패 원인을 그대로 기록한다. 봇의 선택률·전투 승률은 재미나 최적 밸런스의 증거가 아니다.

DOM 테스트는 빌드된 프로그램을 JSDOM에서 실행해 진입·조작·예측·저장 복원·중복 지원 방지를 확인한다. 실제 브라우저 렌더링·휴대폰 터치·화면 겹침·스크린 리더·프레임률·사용자 재미는 미검증이다. 이전 브라우저 차단 정책을 우회하거나 재시도하지 않았다.

## 현재 남긴 범위

전국 지도·추가 도시 유형·영구 메타 콘텐츠 해금·새 장수 합류 시나리오·도시 상실/철수·직접 재방어 전투·다층 인구 정치·청사진 도시 간 기술 전수·새 도시 전용 시네마틱 일러스트/음성은 미구현이다. 제도·인재를 독립된 네 번째 완성 빌드로 확장하지 않았다. 진궁의 정제·할인과 문서고·덱 정제는 혼합 조합으로 제공한다.

도시 구역은 독자 제작 SVG/CSS 약도다. 기존 곽가·진궁 초상을 사용하며 다른 담당 장수는 이름 표식으로 표시한다. 에셋 오류 시 이름을 남기는 fallback이 있다. 상용 게임 화면·지도·아이콘·초상·음원을 복제하지 않았다. 고대 도로 및 도시 구역의 정확한 복원이라고 주장하지 않는다.
