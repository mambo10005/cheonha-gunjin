# 천하군진 수동 브라우저 검증 안내서

현재 로컬 작업본 v0.4.0을 사용자가 직접 실행해 무장 대결·설전·외교, 저장 복원, 화면을 점검하는 절차다. 기준일은 2026-10-09다. 브라우저 보안 정책과 관리자 설정을 변경하지 않으며, 에이전트의 브라우저 재접속·우회도 수행하지 않았다.

이 안내서의 **예상 결과는 현재 코드와 자동 테스트에 근거한 확인 기준**이다. 실제 브라우저에서 사용자가 확인한 결과가 아니다. 수동 확인 상태는 모두 **미검증**으로 시작하고, 아래 기록 양식에 관찰 결과를 채운다.

## 1 설치와 실행

이번 구현이 들어 있는 현재 작업 폴더는 다음과 같다.

`C:\Users\mambo\Documents\Codex\2026-10-09\mam\work\mambo1`

배포용 소스 복사본은 `C:\Users\mambo\Documents\Codex\2026-10-09\mam\outputs\mambo1`이다. 다른 위치에 소스 ZIP을 풀었다면 그 안의 `package.json`이 있는 폴더에서 실행한다. 현재 변경은 GitHub에 푸시하지 않았으므로 원격 저장소를 새로 내려받은 것만으로 이 안내서의 v0.4 기능이 있다고 가정하지 않는다.

PowerShell을 열고 다음 명령을 순서대로 실행한다.

```powershell
Set-Location 'C:\Users\mambo\Documents\Codex\2026-10-09\mam\work\mambo1'
node --version
npm --version
node -p "JSON.stringify({version:require('./package.json').version,engines:require('./package.json').engines,scripts:require('./package.json').scripts},null,2)"
npm ci
npm run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

실제 `package.json` 버전은 `0.4.0`, Node 조건은 `>=22.18`이다. 현재 확인한 실행 환경은 Node `v24.12.0`, npm `11.6.2`다. `package-lock.json`이 포함돼 있으므로 설치는 `npm ci`를 사용한다. `dev`는 Vite를 실행한다. `--host`, `--port`, `--strictPort`는 현재 설치된 Vite의 도움말에서 확인한 옵션이다. 명령 입력 후 터미널을 열어 둔다. 검증이 끝나면 해당 터미널에서 `Ctrl+C`로 개발 서버를 종료한다.

`5173`이 이미 사용 중이면 `--strictPort` 때문에 종료된다. 필요하면 사용자 실행 명령의 포트만 `5174`로 바꾸고, 출력된 새 주소를 사용한다. 이때 저장은 별도 주소에 속하므로 이전 포트의 이어하기가 보이지 않을 수 있다. 설치·실행 오류가 나오면 원문을 기록하고 게임 화면 검증을 **미실시**로 표시한다.

배포 빌드를 따로 확인하려면 개발 서버를 종료한 뒤 다음을 실행한다.

```powershell
npm run build
npm run preview -- --host 127.0.0.1 --port 4173 --strictPort
```

`build`는 타입 검사와 Vite 배포 빌드이고, `preview`는 빌드 결과를 제공한다. `npm start`와 Playwright 테스트 명령은 현재 `package.json`에 없다. 개발 서버와 preview는 포트가 달라 같은 저장을 공유하지 않는다.

## 2 접속 주소 확인

터미널에서 `Local:` 뒤에 나온 주소를 그대로 복사해 사용자의 브라우저 주소창에 붙인다. 예시는 다음과 같다.

```text
VITE v8.3.4 ready ...
Local: http://127.0.0.1:5173/
```

위 주소는 예시이며 실제 출력값을 우선한다. `file://`로 HTML을 직접 여는 방식은 이번 절차에 사용하지 않는다. 브라우저에 천하군진 제목과 **새 원정** 버튼이 나타나는지 확인한다.

다음 항목을 따로 기록한다.

- 터미널에 준비 완료와 `Local:` 주소가 나타났는가?
- 해당 터미널이 계속 실행 중인가?
- 출력 주소를 브라우저에서 열었을 때 게임이 나타나는가?
- 안 나타나면 주소, 브라우저 오류 원문, 터미널 출력을 기록한다. `ERR_CONNECTION_TIMED_OUT`과 게임 내부 예외를 구분한다.

빌드 성공 또는 서버 준비 완료만으로 브라우저 연결 성공으로 판정하지 않는다. 현재 환경에서 사용자의 실제 브라우저 접속 성공 여부는 **미검증**이다.

## 3 검증 원정 선택과 시드 유효 여부

제목 화면의 **새 원정**을 눌러 군주 선택 화면으로 간다. 아래 전용 버튼을 사용한다.

| 시드 | 현재 버튼 | 용도와 범위 |
|---|---|---|
| 31001 | 검증 원정 시작 (시드 31001) | 현재도 유효. 이전 규칙의 무장 대결 → 영입 설전 → 외교 거래 → 후속 이동을 확인한다. 군량 20, 전위·곽가·장료, 교리 없음 |
| 51001 | 설전·협정 검증 원정 (시드 51001) | 최신 요구·논거, 지속 협정, 보급 의무, 정예전 지원, 지정 장수 성장을 확인한다. 군량 20, 전위·곽가, 허점 공략 교리 |
| 41001 | 빌드 검증: 수비 반격 / 교대 돌파 / 허점 공략 | 성장과 장착 전술을 일반 전투·대결에서 확인한다. 같은 시드에 선택한 방향을 적용한다 |

**일반 시드 입력칸에 31001 또는 51001을 입력하고 군주를 선택하는 것과 전용 검증 버튼을 누르는 것은 다르다.** 입력칸은 일반 원정을 생성한다. 검증 버튼이 지도·장수·군량을 별도로 구성한다.

검증 버튼은 현재 코드에서 조조·평로 원정으로 시작한다. 선택 화면의 난이도를 바꿔도 검증 버튼에는 반영되지 않는다. 다른 검증 버튼을 누르면 새 원정 저장으로 바뀌므로 현재 기록이 필요한 원정은 먼저 상태와 화면을 기록한다.

31001은 `configureSocialDemo`가 이전 활동 규칙을 지정하므로 최신 설전의 여덟 논거나 지속 협정 두 슬롯의 동작을 확인하는 경로가 아니다. 교리와 장착 전술이 없는 것은 이 검증 원정의 구성이다. 31001의 버튼·경로는 코드에서 확인했으며, 별도 규칙 엔진 실행에서 1층 대결·전투 승리와 2층 영입 설전 진입도 확인했다. **사용자 브라우저에서의 동일 흐름은 미검증**이다.

## 4 무장 대결 설전 외교 확인 순서

### A 시드 31001의 기본 활동 흐름

지도에서는 같은 경로를 반복하기 쉽도록 첫 번째 칸을 선택한다. 시드뿐 아니라 경로·대표·행동·보상 선택도 함께 기록한다.

| 순서 | 사용자 조작 | 코드 기준 예상 결과 |
|---|---|---|
| 1층 대결 제안 | 전위 선택 → 도전 수락 | 화웅의 선봉 무장과 대결 시작. 별도 체력·기세·상대 다음 행동·행동별 예상 변화 표시 |
| 대결 한 행동 | 근거 없이 연타하지 말고 예상 값을 기록한 뒤 강공·견제·방어·승부수 중 하나 선택 | 회차가 한 번만 진행하고 체력·기세가 미리보기와 일치. 기세 부족의 승부수는 비활성화와 이유 표시 |
| 대결 종료 | 결과 확인 → 전투 시작 | 승리 전열 방비 +6, 무승부 +2. 패배·기권 첫 턴 지휘력 -1. 최대 네 선택 이전에도 체력 소진으로 종료 가능 |
| 1층 일반 전투 | 전법 선택 → 필요한 적/열 선택 → 턴 종료 | 대결 후 실제 전열·후열 전투로 진입. 승리 시 전리품 확인과 카드·정예 보물 선택. 둘 다 처리한 뒤 지도로 이동 |
| 2층 영입 설전 | 대표 곽가 → 설전으로 조건 개선 | 군량 1 차감. 합의·신뢰·집중·현재 관심사와 네 답변 표시. 합의 10·신뢰 2 이상 성공, 합의 6·신뢰 1 이상 부분 성공 |
| 영입 조건 확인 | 네 답변 또는 협상 중단 → 결과 확인 → 조건 선택 | 성공 군량 2, 부분 성공 4, 실패 5의 영입 조건. 이 단계에서는 자동 영입되지 않음 |
| 2층 제안 종료 | 이후 비용 비교를 단순하게 하려면 포기하고 진행 | 이미 낸 설전 도전 비용 외 추가 영입 비용 없음. 전위·곽가·장료 유지. 지도로 이동 |
| 3층 상단 외교 | 보급 요청의 조건 수락. 설전은 생략 | 장료를 유지했다면 사절 할인으로 군량 1 소비 후 +5, 순증가 +4. 상단 관계 0→1, 다음 카드 보상 1회 선택지 -1 |
| 4층 상단 외교 | 통행 협정의 조건 수락. 설전은 생략 | 장료 유지 시 군량 2 소비. 다음 이동 3회 군량 비용 -1. 관계 1→2 |
| 5층 이동과 보급 | 산길 보급 칸으로 이동 → 군량 수레 | 기본 산길 이동 비용 2가 1로 감소, 협정 남은 이동 3→2. 군량 수레 +6. 이동마다 남은 회수가 감소하며 0이면 만료 |

영입 후보 이름과 후속 보상은 그때까지의 선택에 따라 달라질 수 있으므로 표시값을 기록한다. 1층 전투에서 패배하면 이후 절차는 **미도달**로 기록하고 같은 검증 버튼으로 새로 시작한다. 특정 행동 순서로 사람 플레이 승리를 보장하지 않는다.

전투 보상은 **넘기고 군량 +2**와 보물의 **받지 않음**을 골라도 진행할 수 있다. 받을 항목을 선택했는지 확인한 뒤 **지도로**를 누른다. 이 절차에서는 게임 상태를 개발자 도구로 편집하거나 승리를 강제로 만들지 않는다.

선택적으로 4층을 새 원정에서 다시 확인할 때 **군사 지원**을 선택할 수 있다. 우호 관계 1 이상에서 기본 지원은 다음 전투 시작 전열 방비 4·적 전원 피해 6, 해당 전투 카드 보상 선택지 -1이며 시작 때 한 번 소비된다. 통행 협정과 같은 장소에서 함께 살 수는 없다. 후속 전투에 도달하지 못하면 지원 검증은 **미도달**이다.

31001의 대결 제안 설명에 성장 보상이 언급되더라도 교리 없는 이 검증 원정에는 성장 선택 버튼이 나타나지 않는다. 최신 전술·성장 확인은 아래 C 절차를 사용한다.

### B 시드 51001의 최신 설전과 지속 협정

다음은 호송과 공동 작전을 함께 확인하는 경로다. 성장 대상 곽가의 분기가 이미 가득 차지 않도록 1·3·5층의 일반 성장 기회에서는 **성장 대신 병력 +8 · 군량 +2**를 선택한다. 회복은 최대 병력을 넘지 않는다. 이것은 확인 절차를 단순하게 하는 선택이며 최적 전략 판정이 아니다.

| 순서 | 사용자 조작 | 코드 기준 예상 결과 |
|---|---|---|
| 1층 상단 | 이번 제안 거절 → 지도로. 성장 화면이 뜨면 회복 대안 선택 | 관계 변화 없음. 두 협정 슬롯을 향촌·의용군에 사용할 수 있음 |
| 2층 보급 | 군량 수레 | 군량 +6 |
| 3층 향촌 | 보급 대신 향촌과 외교 → 곽가 선택 → 설전으로 조건 개선 | 도전 군량 1 차감. 안전·신뢰 요구와 부담 상한, 두 답변 뒤 반론 예고, 정보·신용 표시 |
| 향촌 설전 | 작전 정보 공개 → 부담 양보 → 운영 제안 → 근거 제시 | 정보 공개 후 바로 양보하면 신뢰 추가 +1. 두 번째 답변 후 안전 요구 3→4. 네 선택 뒤 안전 4·신뢰 6·부담 0으로 성공 예상 |
| 호송 수락 | 결과 확인 → 조건 선택 → 협정 체결 | 성장 보상으로 전환하지 않은 성공 조건이면 군량 2 소비, 병력 최대치 내 +4. 활성 협정 1/2. 관계는 아직 0. 지정 보급 후 전열 방비 12 지원 |
| 4층 의용군 | 곽가 선택 → 설전으로 조건 개선. 위의 네 논거를 같은 순서로 사용 | 안전 조건 성공 예상. 향촌 협정으로 신용 논거도 가용하지만 이 순서에서는 사용하지 않음 |
| 공동 작전 서명 | 결과 확인 뒤 대표를 곽가로 다시 선택 → 협정 체결 | 조건 화면 재생성 시 대표 선택이 초기화될 수 있으므로 서명 직전 다시 고른다. 군량 2 소비, 활성 2/2, 성장 대상 곽가. 관계는 아직 0 |
| 5층 지정 보급 | 협정에 표시된 경로의 군량 수레 선택 | 군량 +6, 호송 상태가 보호 지원 준비로 변경. 의약·증원은 호송 의무를 충족하지 않음 |
| 6층 지정 정예전 | 표시된 경로에 진입 → 도전 거절 | 대결 추가 방비 없이 전투 시작. 위의 성공 협정 조건이면 전열 방비 12, 시작 시 각 적 피해 8. 다른 선택·효과를 섞었다면 합산 내역을 함께 기록 |
| 정예전 승리 | 실제로 전법을 사용해 승리 → 전리품 확인 | 향촌·의용군 관계 각각 0→1. 활성 협정 0/2. 공동 작전 성장 대상 곽가 표시 |
| 지정 장수 성장 | 재계산의 선택 장수 성장 / 강화 또는 회복 대안 | 새 곽가의 재계산 1단계 성장. 공동 작전으로 교리 추가는 불가. 이후 정예 카드·보물 보상 선택으로 복귀 |

네 논거 순서는 현재 코드로 계산한 예상이다. 실제 브라우저에서 직접 입력해 위 숫자와 로그를 비교해야 한다. 성공 화면에서 **원정 성장 선택: 거래는 부분 합의로 전환**을 고르면 위 표의 성공 지원 대신 부분 조건과 예치금 2가 적용되므로, 기본 검증에서는 **결과 확인 → 조건 선택**을 고른다.

추가 분기 확인은 같은 검증 버튼으로 별도의 새 원정을 시작해 수행한다.

- **상단 후원:** 1층에 기본 협정을 서명하면 군량 1 소비 후 +5, 활성 1/2, 관계 변화 없음. 이행 전 군량 보급에 +1. 지정 6층 전투 승리 때 카드 보상을 군량 +3으로 전환하고 정예 보물은 유지, 관계 +1. 성공 설전 후 서명은 즉시 보상이 +6이다.
- **실물 군량과 중단:** 설전 도전의 군량 1과 별도로 실물 군량 제시가 군량 2를 즉시 소비한다. 중단·거절해도 그 2가 돌아오지 않는지 확인한다.
- **실패 협상:** 향촌에 활동 권한 약속을 사용하면 부담 2가 상한 1을 넘는다. 종료 뒤 기본 조건으로 재제안 또는 거절로 진행 가능한지 확인한다. 같은 장소에서 두 번째 설전은 불가다.
- **부분 합의:** 결과가 부분 성공이면 예치금 2가 기본 서명 비용에 추가되고 이행 때 반환된다. 설전 성장 선택으로 부분 조건을 만든 경우도 구분해 기록한다.
- **협정 포기·경로 이탈:** 지도에서 협정을 포기하거나 지정 보급/전투 층에서 다른 칸으로 이동하면 관계 -1·군량 -2(최소 0), 예치금 몰수, 협정 종료가 예상된다. 동일 종료 대가가 반복 적용되지 않는지 확인한다.
- **미보급:** 지정 보급에서 의약·증원을 받고 다음 층으로 이동하면 호송 만료. 지원 방비가 생기지 않아야 한다.

각 분기는 별도 기록으로 남긴다. 예치금·슬롯·이행 확인을 할 때 이미 다른 분기에서 파기한 원정을 재사용하지 않는다.

### C 시드 41001의 대결 전술과 성장

**빌드 검증: 수비 반격**을 누른다. 1~3층의 일반 전투·보상을 진행하고, 1층 이후 전위의 **응징** 성장 또는 **호위** 성장을 선택한다. 3층 이후 같은 분기를 강화하거나 회복 대안을 고른다. 4층에 대결 제안이 나온다.

전위를 선택하고 서로 다른 전술 최대 두 개를 장착한다. 수비 반격에서는 **반격 준비**와 **호흡 조절**을 확인할 수 있다. 반격 준비는 기세 1이 필요하므로 부족할 때 비활성화되고, 사용하면 대결당 한 번의 사용 제한이 적용돼야 한다. 방어로 실제 피해를 완전히 막으면 반격 준비가 쌓이고 다음 공격에 소비되는지 미리보기·로그를 비교한다.

승리하면 시작 방비 +6 / 원정 성장 / 병력 +8·군량 +2의 보상 경로를 확인한다. 성장·회복을 고른 경우 다음 전투의 대결 방비는 +2다. 장수 성장은 이번 원정에 유지되고 다음 일반 전투·대결에서 같은 발동 원리로 사용되는지 확인한다. 승리하지 못한 보상 분기는 **미검증 또는 미도달**로 남긴다.

## 5 활동 도중 새로고침과 저장 복원

현재 원정 저장 버전은 4다. 진행 중 상태는 행동 뒤 자동 저장한다. 새로고침 후에는 제목 화면에서 **이어하기**를 눌러야 한다. 즉시 활동 화면으로 돌아가지 않는 것 자체는 실패가 아니다.

아래 지점마다 같은 절차를 적용한다.

| 저장 지점 | 새로고침 전에 기록할 항목 | 이어하기 뒤 비교할 항목 |
|---|---|---|
| 31001 대결 한 행동 뒤 | 대표·상대·회차·양측 체력·기세·다음 행동·로그 | 같은 값으로 복원되고 다음 행동이 한 번만 처리되는가 |
| 31001 설전 한 답변 뒤 | 논점/회차·집중·합의·신뢰·군량·대표 | 진행이 초기화되지 않고 도전 비용이 또 차감되지 않는가 |
| 51001 설전의 두 답변 뒤 | 각 요구/충족량·반론 적용·정보·신용·부담·군량 | 반론이나 지급 군량이 되돌아가지 않는가 |
| 협정 체결 뒤 지도 | 활성 슬롯·의무 층/경로·대상 장수·관계·예치금 | 협정이 유지되고 서명 비용·즉시 보상이 다시 적용되지 않는가 |
| 호송 보급 완료 뒤 | 보호 지원 준비 상태·군량·목표 전투 | 이어하기 뒤에도 준비 상태와 지원 조건을 유지하는가 |
| 공동 작전 성장 화면 | 성장 대상·관계·활성 협정 수·후속 보상 | 같은 선택으로 복귀하고 관계·예치금·성장이 중복 적용되지 않는가 |
| 일반 전투 한 카드 사용 뒤 | 턴·손패·적 체력/의도·병력·지휘력·준비 토큰 | 같은 전투 상태로 복원되는가 |

절차는 **한 행동 → 화면 기록 → 새로고침 → 이어하기 → 값 비교 → 다음 행동 한 번**이다. 드롭다운에서 아직 확정하지 않은 대표 선택, 장착 전술 후보, 카드 선택 강조, 열린 도움말 창까지 복원되는 것을 요구하지 않는다. 이미 수락한 대결의 대표·장착 전술과 실제 규칙 상태는 비교 대상이다.

주소의 프로토콜·호스트·포트와 브라우저 프로필을 그대로 유지한다. `127.0.0.1`과 `localhost`, 개발 서버 `5173`과 preview `4173`은 저장을 공유하지 않는다. 다른 시드의 원정을 새로 시작하면 현재 진행 저장을 덮어쓴다. 승리·패배가 확정된 원정은 기록을 반영하고 진행 저장을 지우므로 이후 이어하기가 사라지는 것이 예상 동작이다.

**브라우저 저장소를 사용할 수 없어 임시로 진행합니다. 새로고침하면 원정이 사라집니다.**라는 안내가 보이면 저장 복원 검증을 통과로 표시하지 않는다. 오류 문구와 사용 환경을 기록한다. 저장소를 삭제하거나 콘솔에서 값을 편집하는 절차는 포함하지 않는다.

## 6 데스크톱과 모바일 화면 점검

모든 항목의 초기 상태는 **미검증**이다. 다음 크기는 검증용 제안이며 실제로 확인된 화면 크기가 아니다.

| 화면 환경 | 점검 크기 예시 | 확인 방법 |
|---|---|---|
| 데스크톱 | 1280×800, 1440×900 | 창 크기와 브라우저 확대율 100%를 기록하고 직접 조작 |
| 모바일 크기 모사 | 360×800, 390×844, 가로 844×390 | 사용자 개발자 도구의 기기 모사에서 크기·방향을 바꿔 조작 |
| 실제 모바일 기기 | 기종·브라우저·실제 화면 크기 기록 | 기존에 접속이 허용된 실행 환경이 있을 때 별도 확인. 모사 결과와 구분 |

개발 서버의 `127.0.0.1`은 실행한 PC에서 접속하는 주소다. 휴대전화의 같은 주소는 그 휴대전화를 가리킨다. 이 안내서는 모바일 접속을 위해 서버 공개·방화벽·관리자 설정을 변경하지 않는다. 실제 기기 접속 환경이 없다면 모바일 크기 모사만 확인하고 실제 기기는 **미검증**으로 남긴다.

점검 목록:

- [ ] 제목·군주 선택·세 검증 버튼을 읽고 누를 수 있다.
- [ ] 지도 경로·군량·장수 진형·협정 의무가 겹치거나 잘리지 않는다.
- [ ] 대결의 양측 체력·기세·상대 다음 행동·행동별 예상 값을 읽을 수 있다.
- [ ] 대표·전술 선택 드롭다운을 열고 원하는 값을 선택할 수 있다.
- [ ] 설전의 모든 요구·미충족 이유·논거 비용과 버튼이 스크롤로 접근 가능하다.
- [ ] 비활성 버튼의 이유가 마우스 올리기 없이도 보인다.
- [ ] 협정 비용·만료·포기 대가·성장 대상과 선택 버튼을 구분할 수 있다.
- [ ] 전법 선택 후 적 또는 열을 눌러 사용할 수 있고 턴 종료를 누를 수 있다.
- [ ] 모바일 크기에서는 키보드 단축키와 마우스 올리기에 의존하지 않고 주요 조작이 가능하다.
- [ ] 전투 로그·활동 로그의 긴 문장이 읽히며 불필요한 가로 잘림이 없다.
- [ ] 보상·성장·도움말 창을 끝까지 보고 선택/닫기 버튼을 누를 수 있다.
- [ ] 화면 방향·창 크기를 바꾸거나 새로고침해도 진행 상태가 예상대로 유지된다.
- [ ] 빠르게 두 번 누를 때 회차·군량 비용·협정 보상이 두 번 처리되지 않는다.

터치 모사는 실제 기기의 가상 키보드·주소창 높이·운영체제 동작을 전부 검증하지 않는다. 실제 모바일 결과를 별도 기록한다.

## 7 콘솔 오류와 화면 문제 기록 양식

## 자동 검증과 사용자 플레이 검증의 구분

앞선 작업에서 현재 코드 기준 총 **118개** 자동 테스트가 통과했다. 분리 실행 결과는 규칙·저장·자동 플레이 **113개**, HTML 문구·렌더 불변성 **2개**, JSDOM 화면 통합 **3개**다. 타입 검사와 Vite 배포 빌드도 통과했다. 이 안내서를 작성하면서 코드를 변경하거나 전체 테스트를 다시 실행하지는 않았다.

JSDOM은 실제 브라우저의 화면 배치·폰트·모바일 터치 환경을 검증하지 않는다. 일부 통합 테스트는 결과 화면 입력을 확인하기 위해 고정 승리 상태를 사용한다. 사람 플레이의 전투 승리, 읽기 쉬움, 재미, 실패 원인의 이해 가능성을 증명하지 않는다.

31001은 이번 안내서 작성 중 규칙 엔진으로 별도 진행했으며 봇의 대결 승리→1층 전투 승리→2층 영입 설전 진입을 확인했다. 이것도 수동 브라우저 검증 통과 건수에 합산하지 않는다.

**실제 브라우저 플레이·데스크톱/모바일 시각 확인·사람의 재미 평가는 모두 미검증이다.** 사용자는 위의 확인 항목을 직접 실행하고 관찰한 범위만 통과로 바꾼다. 접속 실패나 전투 패배로 도달하지 않은 후속 항목은 통과로 표시하지 않는다.

## 인물 설전 화면 업데이트

설전 행동은 이제 **패 선택 → 상세 미리보기 → 실행** 순서입니다. 패 선택만으로 라운드·비용은 적용되지 않습니다. 이 문서의 기존 행동 순서는 각 패의 실행까지 완료하는 것을 뜻합니다. 곽가/진궁의 신규 설전 무대 검증 버튼(51001), 성공·부분 합의·결렬 재현과 연출·접근성 체크리스트는 [설전 무대 구현·검증 기록](DEBATE-SCENE.md)에 있습니다. 실제 브라우저 결과는 계속 미검증입니다.


## 시네마틱 설전 갱신 (2026-10-09)

현재 UI와 검증 결과는 [시네마틱 설전 기록](CINEMATIC-DEBATE.md)을 따른다. 곽가/상단 원화 6포즈씩, 군막 원화와 장소별 조명·소품, 가로 손패·선택 오버레이·발언자 전환·수동 대사·고대비·글자 크기 설정을 추가했다. 자동 테스트는 144개 통과이며 실제 브라우저/사용자 플레이/성능/시각 회귀는 미검증이다. 이 문서의 이전 통과 건수는 작성 당시의 역사적 기록이다. 브라우저 보안 정책과 관리자 설정은 변경하지 않았다.
