# v0.3 원정 빌드 — 당시 구현 기록

v0.4에서 두 번째 단위를 완료했다. 현재 설전·협정과 후속 작업은 [ACCORDS.md](ACCORDS.md)를 기준으로 한다. 아래는 v0.3 당시의 규칙·검증 기록이다.

## 완료 범위

이번 작업은 요청의 **첫 번째 완성 단위**를 구현했다. 공통 효과 처리, 교리, 장수 성장, 세 빌드, 대결 전술·성장 보상, 일반 전투 연결이 플레이 가능하다. 설전의 요구 조건과 외교의 지속 의무는 아직 v0.2 규칙이다. 아래의 후속 기능을 완성된 기능으로 화면에 표시하지 않는다.

현재 체크아웃은 v0.2 코드였으며 저장 버전은 2였다. 변경 전에 직접 실행한 테스트 76개, 타입 검사, 빌드가 통과했다. 이 결과는 이전 대화의 검증 보고를 인용한 것이 아니다. 저장 버전은 3으로 올렸다.

## 세 빌드의 완성 흐름

시작에 교리 하나를 선택한다. 방진 / 군령 / 허보 중 해당 방향의 기본 전법 한 장을 시작 덱에 추가한다. 1층 종료 후 첫 성장, 3층 종료 후 강화·혼합·회복, 5층 종료 후 보완을 선택한다. 대결을 거절해도 이 성장 기회는 사라지지 않는다. 성장 대신 자원을 받으면 완성 속도가 늦어진다.

### 수비 반격

- 기본: 방진·견수로 실제 공격을 완전히 막으면 반격 준비 +1, 보유 최대 2. 다음 武 카드의 **첫 피해**에 준비 1 소비 → 피해 +5.
- 성장: 호위는 소비 후 양 열 방비 3, 응징은 추가 피해 4. 같은 분기를 한 번 강화하면 각각 6 / 8.
- 연쇄 예: 완전 방어 → 교리와 응징이 준비 2 생성 → 다음 턴 창격의 첫 피해 6 + 교리 5 + 응징 4 = 15. 강화된 응징은 19. 준비는 전투 내에서 턴을 넘어 유지된다.
- 대결: 방어·반격 준비 전술로 실제 피해를 0으로 막으면 같은 준비가 생성된다. 다음 공격에서 소비하며, 호위의 보호는 대결 체력만 보호한다.
- 약점: 적이 공격하지 않거나 방비가 부족하면 발동하지 않는다. 회복을 포기하고 성장만 고르면 원정 병력이 먼저 소진될 수 있다.
- 대체·혼합: 전위가 없어도 방진으로 발동 가능. 철갑·학소는 첫 완전 방어를 돕는다. 준비 행동 후 공격은 돌파 교리와도 연결된다.

### 교대 돌파

- 기본: 일반 전투에서 防·策 다음 武, 대결에서 방어·견제 다음 공격이면 돌파 준비 +1. 준비 2 소비 → 첫 피해 +10.
- 성장: 선봉은 같은 준비 조건에 +1을 더하며 소비 후 대상의 이번 공격 의도 피해 -2, 강화 시 -4. 귀환은 소비 후 양 열 방비 4 / 대결 보호 4, 강화 시 8.
- 연쇄 예: 군령 → 창격 직전에 교리 + 선봉이 준비 2 생성 → 창격 6 + 10 = 16 → 대상 공격 의도 -2. 큰 피해와 다음 위협 감소가 함께 발생한다.
- 대결: 견제 → 공격 연계 또는 체력 4를 지불하는 결사 돌파 → 준비 소비. 선봉은 이번 상대 행동의 피해를 줄인다.
- 약점: 공격만 반복하면 준비가 없다. 비공격 계열 카드의 비용과 손패 순서를 관리해야 한다.
- 대체·혼합: 군령·방진이라는 기본 전법으로 완성 가능. 기존 전고·돌격은 기본 기세를 이용하며, **돌파 준비는 기존 기세와 별도 자원**이다.

### 허점 공략

- 기본: 허보의 대상 열 변경, 공격 의도 대상에 이간계·교란 적용 → 정보 +1. 다음 武 첫 피해에 정보 1 소비 → 피해 +5.
- 성장: 재계산은 같은 조건에서 정보 +1, 소비 후 전법 1장 뽑기 / 대결 기세 +1. 강화 시 2. 급습은 소비 후 추가 피해 4, 강화 시 8.
- 연쇄 예: 허보 → 교리와 급습이 정보 2 생성 → 창격 6 + 5 + 4 = 15. 급습 강화 시 19. 재계산을 고르면 직접 피해 대신 다음 전법을 확보한다.
- 대결: 견제·허점 유도 → 정보 확보 → 다음 공격에 소비. 보유 전법·교리·성장이 전술 보유 조건을 결정한다.
- 약점: 일반 전투에서 조작할 공격 의도가 없으면 정보가 생기지 않는다. 뽑기 보상은 쓸 지휘력과 공격 전법이 있어야 유효하다.
- 대체·혼합: 희귀 이간계 없이 시작 보완 허보로 발동. 기존 곽가·진궁 능력과 계책→武 연계가 접점이다. 성장 단독으로도 정보를 만들고 소비할 수 있다.

교리가 없는 성장도 자체 준비·소비 규칙을 갖는다. 같은 종류의 교리가 있으면 교리가 소비를 담당하고 장수 성장들이 후속 효과를 낸다. 한 공격에서 준비 종류별 소비는 한 번이다. 같은 교리 중복과 세 번째 교리는 허용하지 않는다. 장수당 한 분기, 최대 2단계이며 분기 전환은 불가하다. 교체 시 해당 장수 성장은 삭제된다.

## 전술과 상대

별도 대결 덱·전술 수집 재화는 없다. 기본 호흡 조절 외에 다음 조건으로 전술을 사용할 수 있다.

| 전술 | 보유 조건 | 비용·효과 |
|---|---|---|
| 반격 준비 | 수비 교리·관련 성장 또는 견수/반격 태세/매복 보유 | 기세 1, 이번 피해 8 감소. 완전 방어면 반격 준비 |
| 허점 유도 | 계책 교리·관련 성장 또는 이간계/교란 보유 | 피해 2, 이번 피해 4 감소, 정보 생성, 상대 방비 제거 |
| 결사 돌파 | 돌파 교리·관련 성장 또는 돌격/측면 기습 보유 | 체력 4, 돌파 준비 +2·기세 +1. 공격하지 않음 |
| 호흡 조절 | 기본 보유 | 이번 피해 4 감소·기세 +2. 공격하지 않음 |

두 전술까지 장착하며 각각 대결당 한 번만 쓴다. 출전 전 비용과 효과를 공개한다. 상대는 관문 수비(방비 축적·견제로 제거), 맹장(방어 후 승부수 +3, 준비 없으면 -3), 유격장(견제 다음 공격 외 반격 2) 규칙을 갖는다. 지형은 이번 대결에 추가 적용하지 않는다. 기존 적의 기본 행동은 공개한다.

## 효과 처리·기간

`core/build.ts`에 타입이 있는 정의와 처리기를 모았다. 발동 시점, 자원 비용, 대상, 활동 범위, 만료, 횟수 제한을 데이터로 정의한다. 효과마다 독립된 스크립트를 실행하지 않는다.

1. 기본 행동 검증·비용 지불.
2. 준비 발생 처리, 교리 → 전열 장수 → 후열 장수 순. 대결은 출전 장수 성장만 참조.
3. 공격 직전 준비 소비. 소비 이벤트는 후속 성장만 부르고 공격 이벤트를 다시 부르지 않는다.
4. 후속 보호·의도 약화·뽑기 적용, 첫 피해에 연쇄 피해 가산. 기존 피해 배수·방비 계산이 뒤따른다. 다중 타격·광역·여포 재발동에 보너스를 중복 적용하지 않는다.
5. 종료 판정·로그. 대결 행동 미리보기는 동일 엔진을 복제 상태에서 실행한다.

각 규칙은 전투 턴 / 대결 회차당 2회 한도, 준비 보유 2, 한 이벤트 큐는 24회 한도다. 한도에 도달하면 이유를 로그에 남긴다. 일반 전투의 장수 성장도 기존 배치 조건·후열 동요를 따른다. 준비는 해당 전투·대결에서 유지하고 종료 시 폐기한다. 교리·성장은 원정 내 유지하며 새 원정에서 초기화한다. 전투 기세·대결 기세·돌파 준비는 서로 전달하지 않는다.

## 저장과 중복 입력

- 저장 버전 3. 버전 1·2는 교리·성장·수령 이력을 빈 기본값으로 변환한다. 기존 지도·덱·개별 카드 ID·RNG·진행 상태는 보존한다.
- 이미 출발한 이전 저장에는 새 교리를 강제로 부여하지 않는다. 새 원정에서 교리를 선택하면 새 성장 흐름을 사용할 수 있다.
- 진행 중 대결의 준비·보호·전술 소모, 일반 전투의 준비·발동 횟수, 성장 선택의 후속 상태를 저장한다.
- 성장 토큰 `camp:층` / `duel:층:열`은 원정에서 한 번만 수령. 선택 후 상태를 전환하고, 대결 결과의 성장·회복 수령도 기록하여 재수령을 막는다.
- 알 수 없는 교리·성장·전술, 중복 교리, 성장한 장수의 소유 모순 등을 불러오기에서 거부한다.

## 검증과 재현

실행 명령:

```text
npm test
npm run typecheck
npm run build
npm run sim -- 40 0
npm run sim -- 40 1
npm run sim:builds
```

최종 결과: 테스트 **96개 통과**, 전체 타입 검사·프로덕션 빌드·차이 공백 검사 통과. 자동 플레이는 군주 2명 × 난이도 2개 × 40회, 총 160회 실행했다. 평로 조조/손권은 50.0%/57.5%, 험로는 40.0%/35.0%였다. 변경 전후 승률을 같은 조건으로 비교한 실험은 아니다.

새 테스트는 세 방향의 일반 전투·대결 연쇄, 같은 시드의 호위/응징 비교, 성장 단독·혼합, 한도, 중복 입력, 대결 전술 비용·소모, 성장 시기·교체 소멸, 미리보기와 저장·이전 저장 변환을 검증한다. JSDOM에서는 실제 화면 버튼과 저장/이어하기를 검사한다. 일부 전투를 짧은 고정 상태로 바꾸는 화면 테스트이며 실제 브라우저 렌더링 검증이 아니다.

군주 선택 화면의 **빌드 검증** 세 버튼은 모두 시드 **41001**과 같은 지도·군단에서 출발한다. 무료 성장 없이 1·3·5층 성장, 4·6층 대결, 8층 동탁으로 이어진다. 성장과 회복을 직접 선택한다. 숫자 시드만 입력하는 일반 원정과는 구분되는 고정 지도 시나리오다. 시드 31001은 기존 활동 회귀 확인용으로 남겼다.

이 시나리오의 자동 플레이는 손패·보상 선택을 최적화하지 않는다. 수비 방향은 4층 패배, 돌파는 8층 승리, 계책은 8층 패배했다. 패배를 강제 승리로 바꾸지 않았다. 세 방향 모두 1층에서 성장했고 일반 전투·대결 연쇄가 실제 발동했다. 일반 시드 조조 40회에서는 각 방향의 승리를 확인했다(수비 71271, 돌파 15838, 계책 245489; 봇과 같은 선택 기준). 시드 하나가 승리를 보장하는 것은 아니다.

봇은 성장 장수를 출전 가치에 반영하고, 방향에 맞는 전술을 장착하며, 승리 성장 보상도 처리한다. 추가 뽑기의 장기 가치를 잘 평가하지 못하여 성장 보상에서는 피해 분기를 우선한다. 이 한계 때문에 봇 결과를 분기 균형이나 사람의 재미로 해석하지 않는다.

**미검증:** 실제 브라우저·모바일 배치·사람의 재미·최적 전략·분기 간 균형. 현재 로컬 게임 파일 연결을 브라우저 도구가 프로토콜 정책으로 차단했으므로 실제 시각 검증을 완료하지 못했다. 기존 `incomingPreview`의 일부 추정 차이와 여포 설명/판정 차이는 이번 단위에서 해결하지 않았다.

## 다음 구현 단위와 이어받을 상태

1. **설전·외교:** 상단의 이익/위험, 향촌의 안전/부담, 인재의 명분/권한을 서로 다른 요구로 구현. 정보·군량 담보·권한의 실제 대가를 반영. 협정 슬롯·의무·기한·포기를 추가하고 지도에 달성 가능한 의무만 생성. 이 단계에서 공통 빌드에 설전·의무 이행 트리거를 추가한다.
2. **정제·경로·위험:** `CardInst.uid`에 개조를 부착하고 복제/제거 규칙과 저장 검증을 확장. 기존 8층의 연결 구조에 정찰 비용·보상 성격·준비 기회를 통합. 대결과 정예에 선택 도전 보상을 구현.
3. **연속 사건·보스:** 남은 층에서 완료 가능한 소수의 데이터 기반 사건, 예고되는 동탁 작전 변형. 소모품은 실제 필요가 확인될 때만 추가.

후속 작업은 저장 버전 3과 `RunState.build`, `BattleState.build`, `DuelState.build`를 기준으로 시작한다. 준비 자원을 원정 공유 재화로 바꾸지 않는다. 기존 설전·외교의 저장 상태와 테스트를 유지하면서 다음 완성 단위를 만든다.
