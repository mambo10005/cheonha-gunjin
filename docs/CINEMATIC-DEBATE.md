# 시네마틱 설전 구현·검증 기록

2026-10-09 현재 저장소 기준. 기존 천하군진을 수정했으며 새 게임을 만들지 않았다. 이 기록은 이전 DEBATE-SCENE.md의 화면 구조·테스트 결과를 갱신한다. 상용 품질 최종 승인 기록이 아니다.

## 기존 화면의 실제 원인

코드 분석: 인물별 presentation이 동일한 도형 SVG/base와 CSS 포즈를 연결했다. 285px 프레임(모바일 155px)이 초상화를 축소했고, speech·goal·4×2 손패·상세·로그·설정이 문서 흐름에서 순서대로 쌓였다. 상세 패널은 최소 높이를 더했다. 동일 카드 표면과 긴 계산문이 논점·인물보다 강했다. 누락 에셋도 기존 도형 얼굴로 돌아갔다. 실제 브라우저로 이전/새 화면을 관찰한 결과는 아니다.

## 구현 범위와 화면

첫 수직 슬라이스는 곽가 1명 + 가상의 상단 교섭관 1명 + 군막 원화 1종이다. 각 인물의 neutral/speak/press/countered/concede/victory를 독립 WebP로 연결했다. 그림 생성 도구로 생성한 회화형 원화이며 전문 원화 최종 승인과 화면 검수는 미완료다. 진궁·향촌 대표·기타 인물은 비식별 실루엣 fallback이다. 이 인물들의 최종 원화를 완료했다고 주장하지 않는다.

후경 원화, 중경 지도·탁자·등잔·깃발, 전경 천막 가장자리·먼지를 분리한다. 관청/상단/향촌/관문은 현재 같은 군막 원화의 조명·소품 변형이다. 장소별 독립 배경 5종이 완성된 상태는 아니다. 이름에도 군막 변형임을 표시한다.

데스크톱은 상단의 간단한 원정 HUD, 좌우 프레임 없는 큰 인물, 중앙 논점 인장·요구·반론 예고, 하단 가로 손패로 구성한다. 기록·계산·설정은 기본적으로 닫힌 도구 모음이다. 발언자에 3~5% 확대와 조명, 상대에 감광을 적용한다. CSS 레이어 이동은 텍스트 레이어를 흐리지 않는다. 모바일은 현재 발언자를 크게, 상대를 작게 두고 발언권에 따라 전환한다. 패는 가로 이동하며 상세는 아래쪽 시트로 열린다. 작은 높이/가로모드/큰 글자에서는 접근을 위해 세로 스크롤을 허용한다. 모든 화면에서 무조건 스크롤이 없다는 주장은 하지 않는다.

여덟 논거는 액션 종류별 먹색 바탕, 제한된 강조색, 프레임·상징·패턴을 다르게 사용한다. 상단에는 일치하는 요구 축과 연계 힌트를 표시하고 수치 계산은 선택 상세에 둔다. 기본 카드에는 이름·소모·핵심 변화가 남는다. 색만으로 논거를 구분하지 않는다. 실제 희귀도 데이터가 없는 곳에 희귀도를 만들지 않았다.

패 선택 → 상세 예측 → 실행 순서다. 선택/hover/focus는 비용과 라운드를 바꾸지 않는다. 취소/Escape는 원래 카드로 초점을 돌리고 상세 안에서 Tab 초점을 유지한다. 실행 직후 규칙 결과를 확정·저장하고 연출만 재생한다. 중도 건너뛰기·새로고침으로 비용·효과를 다시 적용하지 않는다.

## 연출과 규칙의 연결

| 규칙 이벤트 | 카메라/반응 |
|---|---|
| 초기 회담 | establishing, 양측 neutral |
| speechStarted | playerSpeak, 실제 발언 텍스트와 speak/press |
| argumentApplied | clash, 해당 논거 상징의 짧은 충돌 |
| opponentCountered / opponentResponded | opponentSpeak, 상대 반론/응답과 피반론 자세 |
| 고유 능력 발동 | 실제 trait 이벤트의 강조와 인물별 상징 |
| requirementSatisfied | requirementComplete, 해당 요구 인장 |
| debateResolved | resolution, 성공·부분·결렬과 실제 조건 |

요구 인장은 현재 값/목표/예측을 표시한다. 한 번 충족되면 영원히 유지되는 잠금처럼 설명하지 않는다. 부분 합의·성공·실패의 비용/보상/부담은 기존 엔진에서 계산한다. 군량·집중·정보·신용의 수치 규칙은 변경하지 않았다. UI에서 규칙을 재추론해 임의 결과를 만들지 않는다.

대사는 순수한 결정 함수가 실제 이벤트에 선택해 넣는다. 무작위 수열을 소비하지 않는다. 최근 대사 최대 10개를 선택 당시 문자열로 저장한다. 저장 검증은 발언자·회차·길이를 제한한다. 기존 저장의 대사 필드 부재도 허용한다. 카메라·효과 큐는 저장/복원 시 다시 결과를 적용하지 않는다.

다중 포즈 방식 A를 선택했다. 독립 이미지로 손·소품을 바꾸고 140ms 교차 페이드한다. 컷아웃 리깅은 연속 동작에 유리하지만 분리 원화·관절 검수·추가 제작이 필요하다. 현재 미술 자산과 첫 슬라이스에 맞춰 리깅/Spine 의존성을 도입하지 않았다.

## 자산과 성능

인물별 manifest에는 실제 경로, required poses, width/height, neutral fallback, 저해상도 placeholder, 얼굴 기준점, desktop/mobile crop, mirror, 색·소품·소재가 있다. TypeScript manifest가 기준이며 각 인물 폴더에 JSON 사본을 제공한다. 누락 포즈→neutral, 이미지 전체 실패→비식별 인장 fallback, 배경 실패→단색 회담 공간이다. 기존 도형 SVG를 런타임 presentation에서 참조하지 않는다. 저장소에 남은 구형 SVG는 과거 자산이며 신규 화면의 최종 원화가 아니다.

필수 5+선택 victory 6포즈 × 2명, 배경 1종의 합계는 755,254 bytes다. 저해상도 2개는 별도다. 512×512 투명 WebP, 원본 atlas PNG는 저장소 밖에 보관했다. atlas의 세로형 반신을 안전 여백 16px 이상으로 배치한 정사각 텍스처다. 소스 대비 런타임 얼굴 해상도와 모바일 실제 크롭은 추가 미술 검수 대상이다. 원본 손·얼굴·복식과 투명도, 어두운 단색 합성 가장자리는 정적 이미지로 확인했다. 이것은 게임 화면 스크린샷이 아니다.

처음에는 보이는 인물 neutral/저해상도와 배경을 요청한다. neutral 로드 후 현재 인물의 다음 포즈를 준비하고 lowPower에서는 미리 로드를 생략한다. width/height로 레이아웃 자리를 예약한다. transform/opacity 중심이며 입자·패럴랙스·모션을 끌 수 있다. 시스템 폰트 사용으로 외부 폰트 요청을 제거했다. GPU/FPS/메모리/첫 화면 전송 실측은 미검증이다. 파일 크기와 빌드 성공을 성능 측정으로 합산하지 않는다.

## 접근성

빠르게/즉시, reduced motion, lowPower, 입자 끄기, 고대비, 100~150% 글자, 자동/수동 대사, 다음 발언·건너뛰기, 키보드 선택·취소를 구현했다. 모바일에도 건너뛰기를 제공한다. 설정은 원정 상태와 분리해서 저장한다. DOM 초점·설정·취소 테스트는 통과했다. 실제 스크린리더 발음/알림 폭주, 고대비 가독성, 확대 시 겹침과 터치 영역은 미검증이다.

## 사용자 수동 확인

Node >=22.18에서 저장소 디렉터리로 이동해 `npm ci`, `npm run dev`를 실행한다. 터미널이 출력하는 Local 주소를 복사해 사용자가 허용된 브라우저에서 연다. 포트는 출력값을 따르고 file:// 주소를 사용하지 않는다. 기존 MANUAL-BROWSER-TEST.md에 설치·실행·새로고침·오류 기록 양식이 있다.

시드 31001 전용 버튼은 기존 대결·영입 설전·외교 회귀용으로 현재 유효하다. 신규 시네마틱/요구 축은 새 원정 → **설전 무대 검증 · 곽가 (51001)**을 사용한다. 숫자만 일반 시드 칸에 입력하는 것과 전용 검증 버튼은 다르다. 1층 상단 후원 설전에서 곽가와 교섭관 두 원화를 확인한다. 정확한 성공/부분/실패 행동 경로는 DEBATE-SCENE.md의 규칙 검증 기록을 따르며 이번 화면의 사용자 플레이는 미검증이다.

다음 순서로 기록한다:

1. 첫 장면: 장소/의제/양측 이름/얼굴/핵심 요구가 3초 안에 읽히는지 기록. 3초 기준은 아직 실측하지 않음.
2. 패 8장: 프레임·아이콘·이름 차이, 가로 이동, 금지 행동 이유 확인.
3. 패 선택/취소: 상세가 장면 위에 열리고 취소 시 군량·집중·회차 불변인지 확인.
4. 실행: 발언 확대·포즈·실제 비용·요구 변화·반론·고유 발동 확인. 부분/실패에서도 선지급 비용을 숨기지 않는지 확인.
5. 발언 중 새로고침: 확정 상태·대사 기록 복원, 비용/보상 재적용 없음, 연출 진행 대기 없이 다음 선택 가능 확인.
6. 성공/부분/결렬: 실제 약정 조건과 후속 보상/부담 일치 확인.
7. desktop1600×900/laptop1366×768/tablet820×1180/mobile390×844 및 360px/가로모드 확인. 얼굴·손·카드·HUD 겹침과 시트 닫기 접근 확인.
8. reduced/즉시/lowPower/고대비/150% 글자/수동 대사/키보드만 사용/스크린리더 확인.
9. 자산 실패 fixture: 조악한 도형 없이 fallback이 유지되고 실행 버튼은 사용 가능한지 확인.

각 항목의 초기 상태는 미검증이다. 브라우저/화면크기/검증 버튼/대표/선택 순서/라운드/기대값/실제값/콘솔 원문/스크린샷/재현 여부를 남긴다. 자동 테스트 결과를 사용자 플레이 결과로 옮겨 적지 않는다.

## 시각 회귀 실행 준비

`public/verification/debate/index.html`에 시작·발언·반론·고유 능력·요구 충족·환급 불가 비용·부분·성공·실패·자산 누락·reduced·고대비·긴 텍스트의 13종이 있다. 레이아웃 엔진을 쓰지 않는 HTML 생성물이다. visual 설정은 별도 정책상 허용된 환경에서만 사용자가 검토 후 실행한다. 현재 차단된 브라우저의 대체 접근 경로로 사용하지 않는다.

선택 설치: `npm install --no-save --package-lock=false @playwright/test`, `npx playwright install chromium`. 최초 승인 기준 이미지 생성: `npx playwright test --config visual/playwright.config.mjs --update-snapshots`. 생성 이미지를 사람이 검토한 뒤 같은 명령에서 `--update-snapshots`를 빼고 비교한다. 현재 기준 이미지가 없고 설정 자체의 실제 실행도 미검증이다.

설정은 Vite 서버를 연결하는 [Playwright webServer 공식 문서](https://playwright.dev/docs/test-webserver)와 [스크린샷 비교 공식 문서](https://playwright.dev/docs/test-snapshots)를 따른다. 서버의 고정 포트는 5191이며 기존 서버 재사용을 끈다. 테스트는 desktop/laptop/tablet/mobile에서 fixture와 실제 화면 입력/초점/겹침을 검사하도록 작성했다. 테스트 파일 작성과 테스트 통과는 구분한다.

## 남은 품질 승인

전문 원화가의 얼굴·손·의상/시대성·포즈 일관성 승인, 독립 장소 원화와 나머지 인물 확장, 실제 화면 크롭·겹침·가독성·접근성, 중저가 모바일 성능 측정이 남았다. 이번 결과는 동작하는 첫 수직 슬라이스와 검증 기반이며 전체 인물/장소의 상용 원화 제작 완료가 아니다. 기존 전투·원정·덱빌딩과 신규 협정 규칙은 유지했다. GitHub에는 커밋/푸시하지 않았다.
