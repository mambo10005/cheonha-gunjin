# 천하군진 군진 전투 개선 · 구현과 실행 안내

기존 저장소의 카드 전투를 유지하면서 전투 화면을 공간형 군진 장면으로 교체했다. 평야 체험 전투 91001을 제공한다. 상용 게임 품질의 완성 원화·음향·다중 포즈 제작과 실제 브라우저 시각 검수는 남아 있다. 이번 결과를 상용 수준으로 검증 완료했다고 주장하지 않는다.

## 실제 실행

압축을 풀고 `mambo1` 폴더에서 Node.js 22.18 이상으로 실행한다. Windows 터미널 명령은 실제 package.json에 맞춘 것이다.

```powershell
npm ci
npm run dev
```

서버가 출력하는 `Local:` 접속 주소를 사용자가 직접 브라우저에 입력한다. 일반적으로 `http://localhost:5173/`이지만 점유된 포트 때문에 달라질 수 있으므로 출력값을 우선한다. file 주소 차단을 풀거나 브라우저·관리자 정책을 변경할 필요가 없다. 관리 정책이 로컬 서버도 차단하면 우회하지 말고 오류 원문을 기록한다.

타이틀 → 새 원정 → **군진 전투 체험 (91001)**. 일반 시드 입력란에 91001을 입력하는 것은 보통 원정이며, 고정 체험 버튼과 다르다. 기존 61001 설전 체험과 81001 역사 지도 체험은 유지했다.

## 분석 결과와 변경

장수는 개인 체력이 없는 상주 능력이다. 아군 군단 병력은 하나이며 전열·후열 방비와 반격은 독립적이다. 적은 UID별 체력·방비·의도·화상·혼란·이간계·보스 단계를 가진 독립 부대다. 화면의 병사 12개는 군진을 뜻하는 고정 기호이며 병력 수나 사망 수와 대응하지 않는다. 장수 그림에 군단 피해를 적용하지 않는다.

교대는 전투 중 지휘력 1, 조조의 매 턴 첫 교대만 무료다. 목적지 열이 가득 차면 기존 규칙대로 그 열 첫 장수와 교환한다. 열 교대 자체가 적 의도를 바꾸지는 않는다. 허보는 단일 열 공격 목표를 뒤집으며 양 열 공격에는 사용할 수 없다. 이간계는 체력이 가장 높은 다른 적을 공격시키며 혼자 남으면 원래 공격을 수행한다. 교란은 행동을 취소한다.

평야 기병 피해 +3, 산길 첫 계책 비용 -1·후열 피격 +2, 하천 방비 +2·화상 부여 절반, 성채 적 시작 방비 10은 기존 규칙을 유지한다. 새 숲 지형이나 바람 방향, 지형 교대 비용을 임의로 추가하지 않았다. 생성 원화의 평야 전장과 벡터 fallback에 기존 지형명과 실제 규칙을 연결했고, 다른 지형의 고유 배경 제작은 남았다.

| 구분 | 이전 | 이번 구현 |
|---|---|---|
| 전장 | 적 정보 카드·열 정보 패널 | 후열 뒤·전열 앞 배치, 군기와 군진, 독립 적 부대 |
| 위협 | 열별 합산 문장 | 적→실제 열 위치의 경로, 공격 수치, 열별 방비·흡수·손실 |
| 정보 밀도 | 능력·규칙·긴 로그 상시 표시 | 핵심 수치 상시, 능력·지형·전체 기록은 펼치기 |
| 미리보기 | 별도 긴 패널 | 전장 부대와 방어선 위 예상 값, 점선 방비, 상세 계산 펼치기 |
| 조작 | 카드→목표 클릭 또는 무대상 카드 재클릭 | 기존 클릭 유지 + 방향키 목표 순회 + Enter 실행 버튼 |
| 저장 | 규칙 처리 뒤 저장 | 규칙 전체 확정·저장 확인 뒤 UI 전용 사건 큐 재생 |
| 장수 교대 | 열 패널에 이름 재배치 | 군기·장수 슬롯 위치 변경, 실제 비용·이유 사건 표시 |
| 로그 | 긴 최근 로그 상시 | 최근 사건 피드백 + 분류 가능한 전체 기록 |

화면 비율은 데스크톱 설계 목표로 전장 약 60–70%, 손패 약 22–28%, HUD 약 7–10%다. CSS는 가용 높이와 최소 높이로 분배한다. 실제 화면 비율·픽셀 크기·텍스트 개수·터치 조작 횟수는 브라우저에서 측정하지 않았다. 위 비율을 실측 결과로 읽으면 안 된다.

클릭 선택을 기본으로 택했다. 드래그는 좁은 휴대폰 화면에서 카드 설명과 목표를 함께 확인하기 어렵고 놓는 위치가 흔들리기 쉽다. 지금은 카드 드래그를 구현하지 않았다. 마우스로 카드→대상을 클릭하면 2회로 실행한다. 먼저 결과를 확인하려면 카드 선택 후 대상 위에 마우스를 올리거나 방향키를 쓴다. 700px 이하 화면은 카드→목표 탭으로 미리보기를 고정한 뒤 실행 버튼을 누르는 3단계 흐름이다. 목표를 탭한 것만으로 자원이나 카드가 소모되지 않는다. 실행 버튼은 현재 선택된 목표·무대상 카드에 사용할 수 있다.

## 규칙 사건과 연출

`src/core/combat-events.ts`는 전투 상태 외부의 WeakMap 구독을 사용한다. 규칙 함수가 비용·카드 확정·피해 시작·방비 흡수·병력/적 체력 피해·방비 획득·반격 준비/발동·처치·의도 변경·장수/성장 발동·상태·뽑기·버림/소멸·교대·턴·보스 전환·승패·연쇄 제한을 발생 시점에 내보낸다. UI는 카드 이름이나 상태 차이로 공격 사건을 만들어내지 않는다. 전체 기록의 기존 문구도 유지한다.

사건은 순서·출처·대상·열·수치·남은 값·이유·우선순위와 실제 순간의 상태 복제를 가진다. 현재 규칙은 순차적이므로 가상의 동시 그룹을 만들지 않는다. 원정 성장 문구는 현재 장수·교리·보물 기록 분류에 함께 표시하며 개별 원인별 전용 원화 컷인은 미완성이다.

UI는 먼저 최종 규칙 상태를 저장하고 저장 내용이 일치하는지 확인한 다음 사건을 재생한다. 재생 중 전법·교대·턴 종료·결과 확인 입력은 잠근다. 건너뛰기 또는 Esc는 타이머·큐·중간 화면을 버리고 이미 저장한 최종 상태를 표시한다. 저장 실패 시 연출하지 않고 오류를 알린다. 연출은 피해·뽑기·보상 함수를 호출하지 않는다.

새로고침은 중간 연출을 이어서 재생하지 않는다. 최종 확정 상태로 복원하며 선택 카드·호버·큐를 버린다. 기존 저장 스키마에 연출 필드를 추가하지 않았고 기존 마이그레이션을 유지했다. 손패·더미·소멸·RNG·의도·진형·상태·성장·지형은 기존 BattleState로 저장한다.

카드 예상은 `previewBattleState`가 복제 상태에 실제 `playCard`를 적용한다. 적 턴 예상은 복제 상태에 실제 `endTurn`을 실행하고 사건의 공격·흡수와 실제 열별 피해 차이를 사용한다. 반격 사망·이간계의 단독 적 예외·방통 화상 등 실제 처리 순서를 반영한다. 적의 개별 의도 수치와 열의 전체 손실 예상은 다른 정보다. 전위 반격은 **그 열 공격의 연타가 끝난 뒤** 발동하며, 매 타격 직후 발동하는 것으로 바꾸지 않았다. 여포 불만 같은 열 공격 외 병력 손실은 턴 종료 옆의 그 외 손실과 종료 후 군단 병력으로 추가 표시한다. 피해량의 상세 출처는 기록에서 확인한다.

헤드리스 자동 플레이는 기존 평가용 근사식 `incomingEstimate`를 계속 사용한다. 기존 정책의 행동 우선순위를 바꾸지 않기 위해 UI의 정확한 적 턴 계산과 분리했다. 숫자 예상은 전체 장면 스냅샷 없이 사건 사실만 수집한다.

연출 강도는 기본 사건·연계 사건·결정적 사건 세 단계다. 군진 밀림·방어선 반응·짧은 출처/효과 띠·처치·결과를 사용한다. 카드마다 전체 화면 컷인을 띄우지 않으며 카메라를 크게 흔들지 않는다. 카메라 상태는 전장/예상/아군 행동/적 행동/반격으로 구분하되 지금은 충돌선·효과 강조 수준이다. 전문적인 줌·이동·다중 포즈·입체적인 돌진/먼지·부대 교대 이동 보간은 미완성이다.

## 91001 권장 체험 순서

시작은 전위 전열·곽가 후열, 황건병 1·궁수 2·황건병 3이다. 지휘력 4, 첫 손패 창격·방진·반격 태세·허보·군령. 황건병은 전열 6씩, 궁수는 후열 6을 노린다.

1. **방진**을 선택하고 전열에 마우스를 올린다. 예상 방비 0→5, 전열 공격 12 중 흡수 5·손실 7을 확인한다. 취소하면 자원이 바뀌지 않아야 한다.
2. **허보**를 황건병 1에 사용한다. 해당 목표가 후열로 바뀌고 곽가가 첫 계책에 지휘력 +1·카드 1장을 준다. 허보 비용은 기존 데이터대로 0이므로 지휘력 4→5다. 두 번째 계책은 그 턴 곽가의 추가 뽑기를 다시 발동시키지 않는다.
3. **반격 태세**를 사용한다. 전열 방비 +4·반격 준비 +4. 준비 시 적에게 즉시 피해가 들어가면 안 된다.
4. **방진**을 전열에 사용하거나 **창격**으로 적 하나를 공격해 예상 병력 손실과 적 체력 변화가 달라지는지 비교한다. 반격은 실제 전열 공격을 받았을 때만 발동한다.
5. **턴 종료**를 누른다. 적 행동→방비 흡수→군단 손실→실제 반격→다음 의도·턴 시작을 기록에서 확인한다. 전위는 전열 공격 뒤 기본 반격 3+당시 남은 전열 방비 절반을 더한다.
6. 전위 **교대**를 사용한다. 조조의 해당 턴 첫 교대는 무료, 다음 교대는 지휘력 1. 전위를 후열에 두면 전열 조건 능력이 정지한다. 적 목표 열 자체는 교대로 바뀌지 않는다.
7. 연출 중 **건너뛰기**를 누른다. 자원·체력·손패·난수가 추가 변경되지 않아야 한다. 실행 직후, 연출 중, 완료 뒤 각각 새로고침하고 **이어하기**를 눌러 최종 상태가 동일하게 복원되는지 확인한다.
8. 승리/패배는 실제 전투로 확인한다. 정적 승리·패배 장면이나 자동 테스트를 사용자 플레이 승패로 간주하지 않는다. 결과 확인을 연속 클릭해 보상·결과가 중복 적용되지 않는지 확인한다.

## 화면·접근성 확인

1440×900 데스크톱은 전장·손패·턴 종료·HUD가 기본 스크롤 없이 보이는지 확인한다. 1280×720 노트북은 전열·후열·적 의도가 겹치지 않는지, 카드 긴 효과와 상세 펼치기가 잘리는지 확인한다. 1024×768 태블릿은 손패 가로 스크롤과 목표 터치 영역을 확인한다. 390×844 모바일은 적 3부대와 두 아군 열을 세로로 함께 표시하며 손패를 가로 스크롤하고 지휘력·턴 종료 영역을 아래에 고정한다. 모바일 페이지 스크롤은 허용한다. 단순 전체 화면 축소나 전열/후열 숨기기는 사용하지 않았다.

1–9 카드 선택, 좌우 방향키 유효 목표 순회, Enter 실행, Esc 취소/연출 건너뛰기, E 턴 종료. Tab으로 카드·교대·설정·기록에 접근할 수 있는지 확인한다. 화면 설정은 원정 저장과 별개로 유지한다. 글자 100/125/150%, 고대비, 움직임 줄이기, 먼지 끄기, 보통/빠름/즉시 속도를 제공한다. 실제 소리가 없고 흔들림·자동 대사도 사용하지 않는다. OS reduced-motion도 CSS에 반영한다.

설정 150%에서 겹침, 카드 설명 잘림, 모바일 44px 터치 크기와 초점 유지, DOM 교체 때 화면 판독기의 반복 안내는 실제 브라우저 접근성 검수 항목이다. 자동 DOM 검사를 시각·접근성 품질 인증으로 간주하지 않는다.

정적 검토 페이지는 서버 주소 뒤 `/verification/battle/`에서 사용자에게 24개 상태를 제공한다. 이 페이지는 상태 문서이며 실제 전법 클릭 테스트 화면이 아니다. 실제 조작은 91001 체험에서 수행한다.

## 검증 구분

규칙: 새 사건 순서, RNG 불변, 대상 오류, 조건부 반격, 방통 화상, 단독 이간계, 교대 비용, 저장 복원 테스트. DOM: 컴파일한 실제 앱에서 카드 선택·목표 순회·실행·입력 잠금·건너뛰기·새로고침·교대·움직임 줄이기·이미지 실패 fallback·턴 진행 검사. 정적 장면: 24개 문서의 구조·필수 제어·NaN/undefined 없는지 검사.

전체 자동 테스트 199개 통과, 실패 0. 모바일 목표 확인·글자 배율·턴 종료 후 병력 표시·생성 원화·인물 컷인까지 반영한 최종 전체 검사도 199개 통과, 실패 0이다. 최신 집중 검사 12개도 통과했다. 규칙 9 + 실제 컴파일 앱 DOM 1 + 기존 화면 통합 2의 집중 검사 로그도 함께 제공한다. 최종 개수와 성패는 배포 `verification/battle-release-test.log`를 기준으로 한다. 타입 검사·빌드·에셋 검사와 별개로 실제 브라우저 플레이·픽셀 레이아웃·모바일 기기·화면 판독기·FPS는 **미검증**이다. 브라우저 접근 차단을 우회·재시도하지 않았고 보안·관리자 설정을 변경하지 않았다. 새 브라우저 오류를 직접 발생시키지 않았으므로 오류 문구를 만들어 기재하지 않는다.

CPU/산출물 크기는 `verification/battle-measurements.json`과 `battle-build.log`를 참고한다. Node 측정은 미리보기/수치 계산/HTML 생성 시간과 특정 사건 큐의 JSON 크기만 측정한다. 브라우저 렌더 속도·메모리 피크·실제 터치 지연을 의미하지 않는다. WebGL/개별 병사 시뮬레이션/외부 지도·게임 엔진을 추가하지 않았다.

## 에셋·출처와 남은 제작

`src/data/battle-presentation.ts`에 초상/전투/컷인 슬롯·군기·세력색·군진 표식·idle/command/attack/guard/counter/damaged 포즈·대표 효과·앵커·모바일 크롭을 모았다. UI에 장수별 파일 경로 조건문을 분산하지 않는다. 곽가는 기존 자체 생성 초상 1장을 재사용하고 전위는 이번에 생성한 반신 원화 1장을 연결했다. 나머지 원화 없는 장수는 군기·이름 fallback이다. 다른 인물 초상을 전위로 가장하지 않는다. 포즈 슬롯은 현재 같은 원화를 재사용하며 포즈 제작 완료로 표기하지 않는다. 이번에 생성한 두 PNG 합계는 5,877,163바이트다. 모바일 전송량과 원화 디코딩 비용 최적화는 추가 검수 항목이며 작은 벡터만 사용한 경우와 동일한 로딩 성능을 주장하지 않는다.

평야 풍경과 전위 반신은 built-in image_gen으로 독립 생성했다. `docs/art/BATTLE-GENERATED.json`에 최종 프롬프트 전체·파일·해상도·알파·생성 출처를 기록했다. 원화 자체를 시각 확인했으며 게임 안 합성의 실제 브라우저 검수는 미실시다. 군진·표식과 배경 fallback은 자체 SVG/CSS 그림이다. 외부 상용 게임의 배경·UI·병사·음향을 가져오지 않았다. 곽가 기존 원화의 생성 기록·관리 기준은 `docs/art/ASSET-PROVENANCE.md`·`ASSET-SPEC.md`를 따른다. 새로운 역사 지도 데이터를 이 전장 배경에 복제하지 않았다. 음향 manifest는 빈 상태로, 저작권 확인된 녹음이 생기기 전까지 재생하지 않는다.

상용 수준을 위해 남은 항목: 생성 원화의 전문가 검수와 여타 장수 원화, 전용 6포즈·군기·공격/방어/반격 모션, 평야 배경 전문가 최종 승인 및 산길·나루·성채별 레이어, 지형별 먼지/수면/불길, 적 병종별 원화, 장수별 추가 컷인·교대 보간, 라이선스 확인된 충돌/군기/카드/승패 음향, 실제 브라우저·모바일 시각/성능 검수. 곽가 첫 계책·전위 실제 반격에는 원화와 실제 원인/수치를 담은 짧은 컷인 띠가 연결된다. 궁수·노병은 데이터상 이름에 맞춘 활·노 기호를 사용하고 나머지는 일반 군진으로 표시한다. 현재 일반 군진 기호는 기능용 시각 표현이며 최종 병사 원화가 아니다. 선택적 위험·추가 보상, 전투 진입 전 미확정 준비 단계도 이번에는 새 규칙으로 추가하지 않았다.

권장 원화 발주 규격: 평야 레이어 2048×1152, 투명 장수 반신 1024×1536, 부대 군집 768×512, 군기 256×512, 효과 512×512. 16:9 전체 구성과 390px 세로 크롭을 함께 확인한다. 밝은 문자 영역과 겹치지 않게 채도·명도를 조절한다. 프롬프트 방향: “후한 말 군진, 독자적인 역사 회화 기반 2.5D 원화, 먼 평야와 낮은 언덕, 먹청·갈색·황금빛 절제, 부대 대치 공간 확보, 문자/로고/UI 없는 레이어, 상용 작품 인물·구도 모사 없음.” 장수는 별도 이름·역할·복식·소도구 설정을 전달하며 원화 결과를 실제 규칙 능력으로 해석하지 않는다.
