# 천하군진 설전 무대 구현·검증 기록

현재 로컬 체크아웃의 기존 게임을 수정했습니다. 설전의 4회 제한, 비용, 요구·신뢰·부담, 반론, 연속 사용 감소, 협정·성장·저장 규칙은 유지합니다. 새 게임이나 별도 판정 모델을 만들지 않았습니다. 이 변경은 아직 GitHub에 커밋·푸시하지 않았으므로 GitHub 원본과 로컬 결과물이 다를 수 있습니다.

## 전과 후

| 영역 | 이전 코드의 구조 | 구현한 구조 |
|---|---|---|
| 원정 정보 | 교리·성장·협정·관계를 긴 패널로 펼침 | 군주·병력·군량·층·덱·규칙·포기는 유지, 원정 상세는 접기 |
| 설전 무대 | 인물 이름을 한 문장으로 표기 | 좌우 흉상, 적성·집중·특성·상대 성향, 중앙 발언·논거 표식 |
| 논점 | 모든 축과 요구 없는 수치까지 평문으로 나열 | 실제 요구와 신뢰만 2~3개 표식, 현재/요구·충족 문자, 부담은 별도 상한 표시 |
| 선택 | 모든 행동에 긴 전후 예상 문구 상시 표시 | 짧은 논거 패, 포커스/호버/선택 상세 미리보기, 별도 실행 버튼 |
| 로그·결과 | 전체 로그 상시 노출 | 최근 발언·반론은 무대, 전체 기록은 접기, 결과 인장·비용·조건·후속 의무·성장 대가 |

원래 `.activity-grid`는 패널을 동일 크기 열로 배열하고 긴 설명·예상을 전부 펼칩니다. `.node-screen`은 폭을 900px로 제한하며 원정 상태 패널이 설전 앞에 쌓입니다. 인물 무대나 논점 중심 영역이 없어 공간과 정보의 우선순위를 제어하기 어려운 구조였습니다. 실제 빈 공간, 픽셀 배치, 대비, 모바일 줄바꿈은 브라우저에서 직접 확인하지 못했습니다. 따라서 위 문제 진단은 코드 구조 분석이며 실제 화면 관찰 결과와 구분합니다.

와이어프레임은 `docs/DEBATE-WIREFRAME.html`에 있습니다. 실행 구현은 `src/ui/debate-scene.ts`, `debate-playback.ts`, `style.css`입니다.

## 인물·포즈·에셋

검증 인물은 곽가·진궁, 상대는 상단 교섭관·향촌 대표입니다. 대기·발언·압박·반론을 받음·우세·양보를 CSS transform, 조명과 채도로 표현합니다. 작은 대기 이동은 8초 주기로 2px이며 강한 효과는 반론·연계·최종 결과에 한정합니다.

모든 그림은 이번 작업에서 직접 작성한 SVG 임시 흉상입니다. 기존 게임이나 인터넷 이미지를 사용하지 않았습니다. 화면에 ‘자체 제작 임시 에셋’을 표시합니다. 최종 고품질 일러스트는 아직 없습니다. 재야 선비와 다른 장수는 공통 흉상을 사용하며 이름·적성·특성은 실제 인물 데이터로 표시합니다.

`src/data/debate-presentation.ts`가 경로·기준점·확대 범위·반전 가능 여부·포즈 목록·색상·시그니처·fallback을 관리합니다. UI에 장수 ID 조건문을 흩뿌리지 않았습니다. 현재 기준점은 50/95, 표시 초점은 50%/28%, 확대 범위는 1~1.06입니다. 개별 포즈 그림 대신 기본 흉상 한 장을 이동합니다. 이미지 공간을 먼저 확보하고 현재 참여 인물의 그림만 로드합니다. 누락 인물·포즈는 공통 인물·대기 포즈로 대체합니다. 그림 로드 실패는 대체 그림, 대체 그림도 실패하면 이름 첫 글자로 표시하며 행동을 막지 않습니다.

| 최종 에셋 사양 | 권장값 |
|---|---|
| 원본 | 1024×1280 또는 840×1000 흉상 |
| 표시 | 데스크톱 약 220~285px 높이, 모바일 약 155px 이하, 얼굴 중심 크롭 |
| 배경 | 투명 WebP 또는 PNG |
| 안전 영역 | 외곽 10%, 얼굴은 상단 15~45%, 흉상 중심을 중앙 30~70%에 확보 |
| 무기·문서 | 얼굴·요구 표식과 겹치지 않게 아래쪽, 외곽 잘림을 허용 |
| 용량 목표 | 본 이미지 150~300KB 이하, 저해상도 420×500 50~100KB 이하 |
| fallback | 자체 제작 SVG → 텍스트 초상, 포즈 누락은 idle |
| 현재 파일 | `public/assets/portraits/{guojia,chengong,merchant,elder}/base.svg`, `fallback.svg` |

곽가의 시그니처는 기록을 드러내는 먹선(`reveal`), 진궁은 신뢰를 묶는 선(`bind`)입니다. 각각 해당 행동에서 실제 연계·특성·요구 충족 이벤트가 있을 때만 발동합니다. 이 연출은 역사적 사실 설명이 아니며 추가 규칙 효과도 없습니다.

## 행동·이벤트 연결

| 행동 | 표현 | 실제 대가·결과 출처 |
|---|---|---|
| 근거 제시 | 문서 심벌과 논점 먹선 | 엔진의 명분·이익·신뢰 이벤트 |
| 반론 정리 | 기울어진 먹선·파열 표식 | 명분 증가·신뢰 감소 |
| 부담 양보 | 연결선·집중 회복·신뢰 표시 | 양보 집중, 중재·정보 직후 연계 |
| 운영 제안 | 지도 선·이익/안전 표식 | 실제 적용된 축별 증가량 |
| 작전 정보 공개 | 서신 표식·후속 연계 | 정보 1 소비, 안전 증가, 다음 양보 개방 |
| 실물 군량 제시 | 군량 표식·즉시 지불 표시 | 군량 -2, 환급 없음, 부담·보급 운영 |
| 활동 권한 약속 | 봉니 표식 | 권한·명분·부담, 수락 시 다음 보상 제한 |
| 협정 신용 활용 | 협정 인장 표식 | 신용 1 소비와 신뢰·안전·이익 |

`core/debate-events.ts`의 영수증 이벤트를 구형 `debate.ts`와 최신 `negotiation.ts`가 계산 위치에서 생성합니다. 각 이벤트에는 종류, source, target, value, resource, reason, priority, sequence가 있습니다. UI는 전후 상태 차이를 추정하지 않고 반환된 영수증을 재생합니다. 미리보기는 기존 `previewDebateAction`을 그대로 호출합니다.

순서는 행동 → 집중/자원 비용 → 발언 → 실제 논거 효과 → 특성/연계 → 상대 반론 → 요구 충족 → 판정입니다. core가 순서를 확정하고 UI는 sequence 순서로 읽습니다. 특성 설명에 이미 총 신뢰 변화에 포함된 기여를 명시하여 같은 수치를 두 번 더해 보이지 않게 했습니다. 요구 충족은 수치 증가가 아니라 상태 표식입니다.

core는 즉시 계산을 마칩니다. 저장도 계산 직후 이루어집니다. 재생은 규칙 상태를 수정하지 않습니다. 다음 입력은 연출이 끝날 때까지 잠그지 않으며 새 입력·화면 전환은 이전 대기열을 취소합니다. core의 라운드 토큰 검사가 중복 입력을 거부합니다. 영수증은 저장 상태에 포함하지 않아 새로고침 후 재생·지불·보상이 반복되지 않습니다. 건너뛰면 규칙 상태를 유지하고 영수증 요약을 남깁니다.

대사는 소수의 데이터 문장 중 현재 시드 상태·인물·행동·라운드의 해시로 선택하며 게임 RNG를 소비하지 않습니다. 상대 문장은 미충족 요구·신뢰·부담과 실제 결과에 대응합니다. 실시간 LLM 호출은 없습니다.

## 반응형·접근성·오디오

데스크톱은 좌우 인물/중앙 발언, 하단 최대 두 줄 4열 손패입니다. 태블릿은 인물 크기를 줄입니다. 560px 이하 모바일은 인물을 상단 2열, 중앙 논점을 그 아래, 손패를 2열로 재배치합니다. 긴 예상 결과는 별도 상세 패널에만 나타납니다. 모바일에서 패널은 최대 65vh로 스크롤합니다. 화면 전체를 단순 축소하지 않습니다. 하단 모달 시트 대신 문서 흐름의 상세 패널을 선택하여 다른 조작을 가리지 않게 했습니다.

모든 패는 네이티브 버튼입니다. Enter/Space로 선택하고 실행 버튼으로 확정합니다. 화살표·Home·End로 손패를 이동합니다. 잠긴 패도 포커스할 수 있고 사유를 읽지만 실행 버튼은 생성되지 않습니다. 요구는 심벌·문자·체크·현재/요구 수치로 표현합니다. 결과 피드백은 `aria-live=polite`입니다. 실행 후 다음 손패 또는 결과 확인에 포커스를 돌려줍니다. 터치 버튼 최소 높이는 44px입니다.

연출 감소, 흔들림, 보통/빠름/즉시, 저사양, 효과음 음소거, 효과음/음악 볼륨을 제공합니다. `prefers-reduced-motion` 감지 시 기본 연출 감소·즉시·흔들림 해제를 적용하고 CSS 미디어 쿼리도 둡니다. 개인 설정은 별도 저장 키로 유지합니다. 연출 감소는 큰 이동·흔들림을 제거하고 정보·이벤트 순서를 유지합니다. transform·opacity 위주이며 3D 엔진이나 새 대형 라이브러리는 추가하지 않았습니다.

`debate-audio` 이벤트와 cue 매핑을 준비했습니다. 현재 오디오 manifest는 비어 있어 실제 음원은 재생하지 않습니다. 음악 설정 역시 준비된 인터페이스이며 음악 재생은 미구현입니다. 음원 파일은 향후 직접 제공되거나 적법한 라이선스를 확인한 파일만 manifest에 추가해야 합니다.

## 실행과 수동 확인

Node.js 22.18 이상이 필요합니다. 현재 package.json의 명령입니다.

```powershell
Set-Location 'C:\Users\mambo\Documents\Codex\2026-10-09\mam\work\mambo1'
npm ci
npm run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

개발 서버가 출력한 `Local:` 주소를 사용자가 브라우저에 직접 입력합니다. 터미널을 계속 켜 둡니다. 포트 사용 중이면 실행이 실패하므로 오류를 기록하고 허용된 다른 포트로 명령을 다시 지정합니다. 다른 포트/localhost/127.0.0.1은 서로 다른 저장 공간입니다. 서버 실제 실행·접속은 이번 작업에서 수행하지 않았습니다.

1. **새 원정** → **설전 무대 검증 · 곽가 (51001)** 또는 **진궁 (51001)**.
2. 1층의 첫 사건 선택 → 대표 장수를 곽가/진궁으로 선택 → **상단 후원 / 설전으로 조건 개선**.
3. 패를 선택하고 상세 숫자를 확인한 뒤 **실행**. 선택만으로 라운드·자원이 변하지 않아야 합니다.
4. 두 번째 실행 후 상단 반론이 이익 요구 4→5로 적용되는지 확인합니다.
5. 결과 뒤 비용·후속 의무를 읽고 **결과 확인 → 조건 선택**. 협정 수락 전 보상이 지급되지 않아야 합니다.

아래 예상값은 실제 입구와 규칙 엔진 및 번들 DOM 입력으로 재현했습니다. **사용자 플레이 검증은 미검증**입니다. 정확히 지정된 검증 버튼·대표·행동을 사용해야 합니다. 일반 입력란에 51001만 입력하면 전용 지도/준비를 만들지 않습니다.

| 대표 / 행동 순서 | 예상 결과 | 최종 주요 수치 (협정 수락 전) |
|---|---|---|
| 곽가 / 운영 제안 → 실물 군량 → 근거 제시 → 부담 양보 | 합의 성립 | 이익 6/5, 안전 4/3, 신뢰 5/2, 부담 1/3, 집중 6, 군량 16, 실물 지불 2 |
| 진궁 / 근거 제시 → 운영 제안 → 근거 제시 → 부담 양보 | 부분 합의 | 이익 5/5, 안전 2/3 미충족, 신뢰 6/2, 부담 0/3, 집중 5, 군량 18 |
| 곽가 / 즉시 협상 중단 | 결렬 | 집중 7, 신뢰 1, 군량 18. 기본 조건으로 재제안하거나 거절 가능 |

상대 향촌 대표는 기존 51001의 3층에서 확인합니다. 1층 협정을 거절하고 지도로, 성장 안내는 회복, 2층 보급에서 군량, 3층 피난민에서 **보급 대신 향촌과 외교** → 호송 설전으로 진입합니다. 곽가 **정보 공개 → 부담 양보 → 운영 제안 → 근거 제시**는 안전 4/4와 신뢰 충족을 확인하는 기존 경로입니다. 향촌은 권한 약속의 부담 2가 상한 1을 초과합니다. 이 경로의 새 화면은 실제 브라우저에서 미검증입니다.

31001의 구형 설전도 새 무대를 사용합니다. 기존 군량·합의·신뢰 기준은 유지하며 최신 요구 축과 혼용하지 않습니다. 진입 전체 순서는 `MANUAL-BROWSER-TEST.md`를 참고합니다.

### 사용자 점검표 (모두 아직 미검증)

- [ ] 데스크톱 1280×800 / 1440×900에서 인물·요구·손패가 겹치지 않는다.
- [ ] 모바일 에뮬레이션 360×800 / 390×844에서 2열 손패, 잠금 사유, 실행·중단·결과 확인이 접근 가능하다.
- [ ] 패 선택/호버/포커스 미리보기와 실제 비용·수치·반론이 일치한다.
- [ ] 곽가 정보 공개 연계, 진궁 양보 중재가 해당 실제 효과에만 반응한다.
- [ ] 일반/빠름/즉시/연출 감소/저사양/흔들림 해제의 가독성과 최종 결과가 같다.
- [ ] 첫 행동 뒤 새로고침 → 이어하기에서 동일 라운드·집중·군량·요구를 복원하고 이미 처리한 연출은 반복되지 않는다.
