# 설전·대결 진입점 조사 (카드 엔진 5차 안정화)

코드 조사 결과입니다(`src/core/city-exploration.ts` `social()`, `src/core/inn.ts`, `src/core/raising.ts`, `src/core/card-engine.ts`, `src/core/city.ts`, `src/core/social-run.ts`, `src/data/city-exploration.ts`). 사람 플레이 결과가 아닙니다.

분류:
- **신형 전체 설전** — 설전 덱 + 논박진(`field`), 상대 원형·의도, 결과 등급·조항. `applyDebateArguments`가 엔진 상태(`engineOf(r)`)와 문맥이 있을 때 `setupField`를 붙입니다.
- **신형 전체 대결** — 대결 덱(`deck`), 상대 의도 덱, `DuelObjectiveDefinition` 등급. `setupEngineDuel(r,s,objective)`.
- **구형 설전** — 설전 덱만(논박진 없음, 반론 규칙 예고형) 또는 덱 없는 반론 설전.
- **구형 대결** — 대결 2판(덱 없음, 합마다 행동 버튼, 상대 고정 순서 4개). `applyDuelLoadout`.
- **간이 판정** — 카드·자원·동행·주사위로 한 번에 결정되는 접근법. 설전·대결 화면 없음.
- **자동 해결** — 조건을 채우면 대결·설전 자체가 생략되거나 결과가 확정되는 경로.

사용자 화면 표기 원칙: 신형만 「설전」「무장 대결」. 구형은 「간이 교섭 · 짧은 문답」「간이 겨루기 · 짧은 겨루기」. 「구형」「신형」「시스템」 같은 개발 용어는 화면에 쓰지 않습니다(`tests/stabilize.test.ts` 진입점 테스트가 문자열을 확인).

## 6. 이번에 신형화한 진입점과 근거

병영 훈련 대표 대결(`barracks` 'duel', 퍼즐 해결 「훈련 대표 대결」 포함).
- 거병 계획 영향: 지휘 인정이 군영 장악 관문의 시작 기세·`duel:trainer-command` 유산에 반영 (우선순위 1).
- 인재 등용 영향: 병영 장악 계획·병사 지지 경로 (우선순위 2).
- 반복 등장: 전위·정보 빌드 완주에서 병영을 지남 (우선순위 4).
목표 `trainer`(훈련 대표의 인정): 지휘 인정 / 인정 / 조건부 인정. 상대 반격형(수세·반격 2·강타·간보기 2·마무리). 자동 정책(목표 인식)으로 지휘 인정을 확인했습니다(`tests/stabilize.test.ts`).

## 7. 남은 구형·간이 판정과 다음 전환 우선순위

1. 시장 「호위 대표와 무장 대결」(`market` 2단계 'duel') — 사라진 장부 의뢰 완결·상단 관계에 영향. 객사 호위 계약 대결(`escort_captain`)과 목표를 공유할 수 있음.
2. 성 밖 「호송대를 위한 대결」(`outside` 'duel') — 호송대 관계·치안. 반복 등장은 낮음.
3. 거병 후 도시 현안 교섭(`city.ts`) — 도시 상태 영향(우선순위 5). 논박진 문맥(`debateContextOf`)이 탐색 사건 기준이어서 현안용 문맥 정의가 필요.
4. 원정 지도 설전·대결 전부 — 별도 작업. 전투 지도의 장수 대결·회담은 거병 전 플레이와 무관.

간이 판정(접근법 `talk/card/investigate/trade/item/companion/risk`, 객사 의뢰 선택지, 퍼즐 비대결 해결)은 설전·대결로 바꿀 대상이 아니라 그대로 둡니다.
